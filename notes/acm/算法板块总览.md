## 〇、总纲

★ **算法题是「板块化」的：解法不是无穷多，而是有限个经典套路的排列组合。**

一道题 = 某个经典板块 + 一点变形/组合。

所以解题不是「发明解法」，而是「**识别**该用哪个板块」。老手看题快，是因为在做**模式匹配**，不是从零思考。

## 一、板块分层结构

```
第 0 层：基础工具（最通用，90% 简单题靠这层 + 第 1 层）
  ├─ 数组 / 字符串 遍历
  ├─ 哈希表 / 计数数组
  ├─ 排序
  ├─ 前缀和 / 差分
  ├─ 二分查找
  ├─ 双指针
  │    ├─ 同向 · 滑动窗口（连续区间）
  │    ├─ 相向 · 对撞（首尾配对 / 收缩）
  │    └─ 同向 · 快慢（原地去重 / 移动元素）
  └─ 位运算

第 1 层：核心思想（跨越所有题型）
  ├─ 枚举 / 暴力
  ├─ 贪心
  ├─ 分治
  ├─ 递归
  ├─ 动态规划（DP）
  └─ 搜索（DFS / BFS）

第 2 层：数据结构
  ├─ 栈 / 队列
  ├─ 链表（单/双、快慢指针、翻转）
  ├─ 单调栈 / 单调队列
  ├─ 堆（优先队列）
  ├─ 并查集
  ├─ 树状数组 / 线段树
  ├─ Trie（字典树）
  └─ 图的存储与遍历

第 3 层：专题算法（较独立、较难）
  ├─ 图论：最短路 / 拓扑排序 / 最小生成树 / 网络流
  ├─ 数论：gcd / 素数筛 / 快速幂 / 组合数学
  ├─ 字符串：KMP / 字符串哈希 / Z 函数
  ├─ 计算几何
  └─ DP 优化
```

★ **越往上越通用，越往下越独立越难。新手优先打透第 0、1 层。**

## 二、板块关系（关键认知）

板块不是孤岛，而是**互相调用、组合**的：

| 关系 | 例子 |
|---|---|
| **组合** | 滑窗 + 单调队列（239）；DP + 前缀和优化 |
| **互相转化** | 部分 DP 题可转成图论最短路；二分答案 + 判定 |
| **同一思想不同载体** | 「单调性」出现在二分、双指针、单调栈中 |
| **层层递进** | 暴力 → 哈希降维 → 双指针 → 单调栈，都是「降复杂度」的加码 |

⚠️ 不要背孤岛，要建立**可组合的知识网**。见新题时想：「它像哪个板块？需要拼几个板块？」

### ★ 跨板块元认知：生命周期与两种淘汰机制

★ **多个板块正在做同一件事：判断「旧元素还活着吗」，不活就丢。**

| 板块 / 题 | 结构 | 「死掉」的判据 |
|---|---|---|
| 滑动窗口（209 / 76…） | 双指针窗口 | `left` 左移放弃 |
| 单调队列（239） | `deque` | 下标滑出窗口（`front < end-k+1`）|
| 哈希映射（存在重复元素 II 的覆盖） | `unordered_map` | 旧下标被新下标取代 |
| 单调栈（下一个更大元素 I / 每日温度） | `stack` | 被弹出（遇到更大元素）|

★ **两种淘汰机制：**

| 机制 | 触发条件 | 例子 |
|---|---|---|
| **过期淘汰** | 超出固定边界（时间 / 窗口） | 滑窗最大值的 `front < end-k+1` |
| **支配淘汰** | 有更优的替代者（更近 / 更大） | 存在重复元素 II 的覆盖、滑窗最大值的踢尾、单调栈的弹出 |

★ **迁移思维：看到「加新元素时纠结要不要删旧的」→ 问「旧元素还活着吗？活着的判据是什么？」**

- 不活着（过期 or 被支配）→ 删
- 活着 → 留

★ **这正是「可组合知识网」的实例：同一个抽象同时解释滑窗 / 单调队列 / 哈希 / 单调栈四个板块。**

## 二·补、★ 难度尺：为什么 LC 难度对我参考价值低

★ **LeetCode 难度衡量的是「模式识别难度」，不是「知识难度」。**

```
Easy   = 常见模式，大部分人见过 / 能想到
Medium = 需要一步转换，或组合两个模式
Hard   = 需要非平凡的关键洞察 / 复杂实现
```

★ **一旦某个模式被「学过 + 归类」，对应的 Hard 就塌成 Easy。**（滑窗最大值 / 最小覆盖子串都标 Hard，学完板子后不难）

### 实证：难度与实际感受脱节

| 题目 | LC 标 | 实际感受 |
|---|---|---|
| 滑动窗口最大值（239） | Hard | 学完单调队列后不难 |
| 最小覆盖子串（76） | Hard | 独立写出 |
| 存在重复元素（217） | **Easy** | 反而翻了两次笔记（insert/pair）|
| 存在重复元素 II（219） | Medium | 一次过 |

### ★ 对我该用的「难度尺」

```
难度 = ① 需要哪个 / 几个板块
      ② 有没有关键洞察（「啊哈」点）
      ③ 实现复杂度（边界、易错）
```

### ★ 关键推论：卡在哪，决定该补哪块

★ **卡在 Easy / Medium → 多半是「语言 / 实现」坑；卡在 Hard → 才是「算法 / 思维」坑。**

| 现象 | 病根 | 补什么 |
|---|---|---|
| (Easy) 卡在 `insert`/pair（217） | 实现细节 | 补语言 / 容器 API |
| (Hard) 写完就过（239） | — | 算法思维已跨过 |

★ **LC 难度的残余用途（仅两个）**：
1. **判断是否超出当前板块**：Hard 若只用学过的板块能解 → 模式识别题；需要没学的 → 提示该补板块
2. **参考「需要拼几个板块」**（这才是对我的真难度）

## 三、信号 → 板块 对照表（核心工具）

★ 每做一道题，就往这张表里补充一行。这是最值钱的产出。

| 题目信号 | 对应板块 |
|---|---|
| 连续子数组/子串 + 最长/最短 | 滑动窗口 |
| 连续区间 + 和/计数（可离线） | 前缀和 / 差分 |
| 多次区间求和 | 前缀和 |
| 多次区间加值 | 差分 |
| 「多少个子数组满足和=k」 | 前缀和 + 哈希 |
| 有序数组 + 查找配对 | 对撞双指针 |
| 两端取最大 / 反向构造 | 对撞双指针（从末尾填） |
| 求最大容量 / 面积（依赖宽度）| 对撞双指针（移动矮端，**不能排序**）|
| 区间重叠 / 合并 | 排序（右端点选最多 / 左端点合并）+ 贪心 |
| 求最大/最少子集（区间调度） | 按右端点排序 + 贪心 |
| 「能否到达 / 最远可达」 | 扫描型贪心（维护 reach）|
| 答案有单调性 / 「最小化最大值」 | 二分答案 |
| 「最小化最大值」/「最大化最小值」 | 二分答案 + 贪心分段 |
| 方案数 / 最优值 + 重叠子问题 | 动态规划 |
| 第 k 大 / 动态最值 | 堆 / 单调队列 |
| 「下一个更大/更小元素」 | 单调栈 |
| 滑动窗口内的最大值/最小值 | 单调队列（239） |
| 连通性 / 分组 / 环检测 | 并查集 / DFS |
| 最短步数 / 层级扩散 | BFS |
| 最短路（带权） | Dijkstra / SPFA |
| 字符串匹配 / 前后缀 | KMP / 字符串哈希 |
| 区间查询 + 单点更新 | 树状数组 / 线段树 |
| 前缀相关 | Trie |
| 求模 / 大数运算 | 快速幂 / 数论 |
| 只查某元素是否存在 | 哈希集合（不需要窗口） |
| 需要「值 → 位置 / 次数 / 答案」的映射 | 哈希表（unordered_map） |
| 边遍历边问「之前见过吗」 | 哈希表 + 先查后记 |
| 一 key 对多个结果（分组 / 分桶）| 哈希表，值用 vector |
| 求「连续序列」长度（无序列）| 哈希集合 + 只从起点扩展 |

| 找出字符串中第一个匹配项（28） | 字符串匹配 | KMP 前置（暴力匹配） | ✅ |
| 最长回文子串（5） | DP / 中心扩展 | 第 1 层待系统学 | ✅ |

### ★ 三种双指针（本人已全部踩过）

| 类型 | 方向 | 用途 | 做过 |
|---|---|---|---|
| **滑动窗口** | 同向 | 连续区间 + 可增量维护状态 | ✅ 8 题 |
| **对撞** | 相向 | 首尾配对 / 收缩 | ✅ 4 题 |
| **快慢** | 同向（不同速） | 原地去重 / 移动元素 / 判环 / 找中点 | ✅ 3 题（数组版）|

★ **快慢指针的链表版（判环 141 / 142、找中点 876）待链表板块开坑时一起学。**

## 五、板块化学习的正确姿势

### 原则 1：按板块刷，不按难度刷

- ❌ 今天滑窗、明天 DP、后天图论 → 每次从零开始，学不牢
- ✅ 一个板块连续刷 8~15 道，直到「看到题就知道套路」，再换下一个

### 原则 2：每板块产出「模板 + 变体 + 坑」

每份专题笔记固定结构：

```text
模板   —— 通用骨架
变体   —— 同类题的差异（如滑窗的求最长/求最短/固定长）
坑     —— 踩过的错误（如 last[c] >= left）
练习   —— 该板块的题目清单
```

★ **笔记是板块学习的成果物，没有它，刷完就忘。**

### 原则 3：建立「信号 → 板块」条件反射

即上面第三节的表，边做题边补。

## 六、⚠️ 新手高频误区

| # | 误区 | 正确做法 |
|---|---|---|
| 1 | 以为要先背完所有板块才能做题 | 做题 → 遇不会 → 补板块 → 归纳，循环起来 |
| 2 | 按题目难度随机刷 | 按板块连续刷透再换 |
| 3 | 刷完不记笔记 | 每板块产出模板/变体/坑 |
| 4 | 把板块当孤岛背 | 建立可组合的知识网 |
| 5 | 只记「这题用滑窗」 | 记「什么信号 → 用什么」，即模式匹配 |
| 6 | 哈希表「先记后查」读到自己 | 问「当前 vs 过去」时**先查后记**（先消费者，后生产者）；判断存在用 `count` / `find`，别用 `mp[k]` |
| 7 | 只关心 Big-O 不看常数 | 同一量级内的快慢由**内存布局**决定：能连续就连续、能 `reserve` 就 `reserve`、能 `vector` 就 `vector`（详见 [C++-内存与调度-速查.md](速查手册/C++-内存与调度-速查.md)）|

★ **板块是「事后总结」的，不是「事前规定」的。** 地图会随实战不断长出来。

---

## 七、建议的入门顺序

```
双指针 / 滑动窗口  →  前缀和 / 差分  →  二分  →  排序 + 贪心
        →  栈 / 队列 / 单调栈  →  DFS / BFS  →  动态规划  →  图论
```

新手先把这条线走一遍，各板块打通后，第 2、3 层再按兴趣与需要深入。

---

## 八、一句话总结

> **算法题是板块化的：识别板块 + 组合板块 = 解题。**
> 三件事：**按板块刷题**、**每板块产出笔记**、**建立信号对照表**。
> 不要等背完地图才出发——做题、补板块、归纳，地图会自己长出来。

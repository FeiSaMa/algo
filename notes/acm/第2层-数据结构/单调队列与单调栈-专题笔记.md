## 〇、一句话总纲

★ **单调队列 / 单调栈 = 用「单调性」把「永远不可能成为答案」的元素提前丢弃，让队首（或栈顶）直接就是答案。**

它解决的问题是：**「滑动窗口 + 需要最值」** —— 这类需求无法用简单的加减维护。

## 一、为什么需要它（问题的来源）

### 1.1 滑窗家族的分界线

前面 7 道滑窗题，窗口状态都是**「可加减的量」**：

| 题 | 窗口状态 | 能否 O(1) 维护 |
|---|---|---|
| 3 | 字符是否出现 | ✅ |
| 209 | 窗口和 | ✅ 加/减 |
| 567/438 | 字符计数 | ✅ ++/-- |
| 1004 | 窗口内 0 的个数 | ✅ ++/-- |
| 76 | 字符计数 + 覆盖 | ✅ 加/减（判断需 O(1) 优化） |
| **239** | **窗口内最大值** | ❌ **无法 O(1) 加减！** |

★ **239 的分界线：**

- 加进来一个数：`max = max(max, new)` ✅ O(1)
- **移出去一个数**：如果它恰好是最大值 → **得重新找出剩余最大值** ❌ O(窗口长)

**「滑动 + 要最值」天生冲突。**

### 1.2 自然想到的错误解法：排序

**思路**：窗口内元素排序，取最大。

**为什么不行：**

1. 每滑一格都要重排 → O(n·k log k)，比暴力还慢
2. **排序丢失了「位置信息」** → 移出元素时不知道它在哪、有没有过期

★ **核心矛盾：排序是「全量重排」，窗口是「增量进出」。**

### 1.3 可行的替代：multiset（有序容器）

```cpp
multiset<int> ms;                    // 自动有序
*ms.rbegin();                        // 最大值
ms.erase(ms.find(旧值));             // 移出（find 找到那个值）
ms.insert(新值);                     // 移入
```

- 每步 O(log k) → 总 **O(n log k)**，能过但不是最优
- 常数大，且 `erase(find(x))` 要小心（会删掉所有相等的？不，`find` 只删一个）

★ **它解决了「不知道排除哪个」的问题（因为 multiset 能按值查找），但代价是 O(log k)。**

## 二、单调队列是什么

### 2.1 核心思想

★ **不需要知道「所有元素的大小顺序」，只需要知道「谁可能成为最大值」。**

观察：

> 当一个小元素进来时，如果它左边已经有一个**更大的**元素**还留在窗口里**，
> 那这个小元素**永远不可能成为最大值** → **可以立刻扔掉！**

```
窗口: [1, 3, 2]   ← 2 进来时，左边有 3 > 2
       ↑
   1 也永远不可能是最大值（右边有 3）

所以只需要保留 3，1 和 2 都是「废的」
```

### 2.2 数据结构：`deque`（双端队列）

需要的操作：

| 操作 | 位置 | 用途 |
|---|---|---|
| `push_back` | 尾部 | 新元素进队 |
| `pop_back` | **尾部** | 踢掉比新元素小的 |
| `pop_front` | **头部** | 弹掉过期的 |
| `front` | 头部 | 取最大值 |

★ **需要「两头都能进出」→ 只能是 `deque`。**

### ★ 底层视角：deque 到底是什么

- **`vector`**：一整块连续内存 → 头部插入要搬全部（O(n)）
- **`deque`（double-ended queue）**：**分段连续** —— 多块缓冲区 + 一个「块指针数组」串起来
  ★ 所以头尾插入/删除都是 O(1)（最多新开一块）
  ⚠️ 代价：随机访问 `dq[i]` 要「算块号 + 块内偏移」→ 比 vector 多一层计算（但 239 只访问头尾，不受影响）
  ★ 详细对比见 `速查手册/C++-内存与调度-速查.md` 第 3.2 节。

- `vector`：头部操作 O(n) ❌
- `queue`：不能从尾部踢 ❌
- `deque`：两头都是 O(1) ✅

### 2.3 ★ 关键：存「下标」，不存「值」

```cpp
deque<int> dq;          // 存的是 nums 的下标
dq.push_back(end);
```

**为什么不能存值？**

```
nums = [1, 3, 3, 2]，窗口滑走一个 3
dq 里有两个 3 → 该弹哪个？分不出「是哪个 3 过期了」 → 无法判断过期
```

★ **存值 → 丢失位置信息 → 无法判断过期。**

**存下标的两条性质：**

| 性质 | 说明 | 用途 |
|---|---|---|
| **下标递增** | 后进的必然更大 | 队首最老 → **只弹队首**就能清理过期 |
| **值递减** | 踢掉小的之后自然形成 | 队首最大 → `nums[front]` 就是答案 |

```
下标:  [2,  5,  7]
值:    [9,  7,  3]     ← nums[2]=9, nums[5]=7, nums[7]=3
       ↑            ↑
     最大值       最小值（但最新）
```

### 2.4 ★ 「递增/递减」是相对哪个方向？（本人长期困惑点）

★ **根本原因：栈和队列的「老 → 新」方向不同，但两个容器的单调性都描述同一方向。**

```
队列（deque）:
  front（队首，最老） ──────────► back（队尾，最新）
  ↑ push_back 往 back 放

栈（stack）:
  bottom（栈底，最老） ─────────► top（栈顶，最新）
  ↑ push 往 top 放
```

★ **两者都是「老 → 新」的方向** —— 因为新元素总是加到「新」的一头。

#### ★ 一张表看透

| | 老的一端 | 新的一端 | 「递减」的方向 | 最大值在哪 |
|---|---|---|---|---|
| **单调队列** | `front` | `back` | **front → back** | **`front`（队首）** |
| **单调栈** | `bottom` | `top` | **bottom → top** | **`bottom`（栈底）** |

★ **两个容器里，「老 → 新」这个方向都是「递减」的。**

★ **区别只在于「从哪头取答案」**：
- **队列**：从 **front（老的）** 取 → 窗口最大值
- **栈**：从 **top（新的）** 取 → 用于「和新元素比」

#### ★ 为什么必然是这个方向

★ **淘汰规则相同：新元素踢掉所有比它小（或相等）的旧元素。**

```
结果：留下的是「越老越大」
→ 老的一头 = 最大（因为小的都被新的大元素踢掉了）
→ 新的一头 = 最小（最新进来的小元素还没被踢）
```

#### ★ 最实用的记法（推荐）

★ **不要记「递增/递减」，记这两句：**

```
单调队列：队首 = 最大值，队尾 = 最新元素
单调栈　：栈底 = 最大值（最老），栈顶 = 最新元素
```

★ **或者一句：**「**越靠『老』的一端，值越大**」

#### 验证

```
239 nums=[1,3,-1]，dq 最终 [1,2] → 值 [3,-1]      （front→back 递减 ✓）
739 temp=[75,71,69]，st 最终 [0,1,2] → 值 [75,71,69]（bottom→top 递减 ✓）
```

## 三、怎么维持「值递减」（不是排序，是「踢」）

### 3.1 操作三件套

```cpp
for (int end = 0; end < n; end++) {
    // ① 踢尾：把尾部所有 <= nums[end] 的踢掉
    while (!dq.empty() && nums[dq.back()] <= nums[end]) {
        dq.pop_back();
    }
    // ② 进队：新元素接上
    dq.push_back(end);

    // ③ 弹过期：队首下标已不在窗口内
    while (!dq.empty() && dq.front() < end - k + 1) {
        dq.pop_front();
    }

    // ④ 输出：窗口已满时，队首就是最大值
    if (end >= k - 1) result.push_back(nums[dq.front()]);
}
```

### 3.2 为什么「踢尾」能保持递减

**归纳法**：假设队列当前已递减，新元素进来：

```
队列 [9, 7, 3]（递减），新元素 5：
  队尾 3 <= 5 → 踢 → [9, 7]
  队尾 7 > 5  → 停
  push 5 → [9, 7, 5]   ← 仍然递减 ✅
```

★ **因为「踢掉所有 ≤ 新元素的尾部元素」→ 剩下的队尾 > 新元素 → 新元素接上后仍然递减。**

### 3.3 ★ 为什么「踢掉是安全的」（不会踢掉未来的答案）

被踢掉的元素（如上面的 7、3）有两个特点：

1. **值 ≤ 新元素** → 新元素在时，它们不可能是最大值
2. **下标 < 新元素** → 它们比新元素**更早过期**

★ **两条合起来：**

> 被踢的元素**既没有新元素大，又比新元素先过期** ——
> 它在新元素有效期内不可能是最大值；在新元素过期后它更早就过期了。
> → **它一辈子都当不上最大值 → 踢掉无损失。**

### 3.4 走一遍完整例子

`nums = [1, 3, -1, -3, 5, 3, 6, 7]`, `k = 3`

| end | nums[end] | 踢尾后 dq | 进队后 | 弹过期 | 窗口满? | 输出 |
|---|---|---|---|---|---|---|
| 0 | 1 | `[]` | `[0]` | — | 否 | — |
| 1 | 3 | `[]`（踢掉0） | `[1]` | — | 否 | — |
| 2 | -1 | `[1]` | `[1,2]` | — | ✅ | **3** |
| 3 | -3 | `[1,2]` | `[1,2,3]` | — | ✅ | **3** |
| 4 | 5 | `[]`（踢1,2,3） | `[4]` | — | ✅ | **5** |
| 5 | 3 | `[4]` | `[4,5]` | — | ✅ | **5** |
| 6 | 6 | `[]`（踢4,5） | `[6]` | — | ✅ | **6** |
| 7 | 7 | `[]`（踢6） | `[7]` | — | ✅ | **7** |

**结果 `[3,3,5,5,6,7]`** ✅

## 四、LeetCode 239 案例（本人独立完成）

```cpp
class Solution {
public:
    vector<int> maxSlidingWindow(vector<int>& nums, int k) {
        deque<int> dq;
        vector<int> maxNums;
        for (int end = 0; end < (int)nums.size(); end++) {
            while (!dq.empty() && nums[dq.back()] <= nums[end]) dq.pop_back();  // ①
            dq.push_back(end);                                                   // ②
            while (!dq.empty() && dq.front() < end - k + 1) dq.pop_front();     // ③
            if (end >= k - 1) maxNums.push_back(nums[dq.front()]);               // ④
        }
        return maxNums;
    }
};
```

- 时间 24ms / beat 52.88%；内存 beat 91%（O(k) 空间）
- ★ **踩坑记录**：第一版把 `push_back(nums[end])`（存值）而不是 `push_back(end)`（存下标）→ `nums[dq.back()]` 越界崩溃
  - **教训：一处「存值/存下标」手滑，全盘崩。**

## 五、⚠️ 避坑清单

| # | 坑 | 正确做法 |
|---|---|---|
| 1 | **存值而非下标** | 必须 `push_back(end)`；否则无法判断过期，且 `nums[值]` 越界 |
| 2 | `dq.front()` 在空队列上调用 | 每个访问前判 `!dq.empty()` |
| 3 | `while` 条件里判空写在 `&&` 右边 | `!dq.empty()` 必须在**左边**（短路求值） |
| 4 | 忘记「弹过期」 | 队首必须保证在 `[end-k+1, end]` 内 |
| 5 | 窗口没满就输出 | 仅 `end >= k-1` 时输出 |
| 6 | 过期判据用值比较 | 用**下标**：`dq.front() < end - k + 1` |
| 7 | 每滑一格重排序 | 用单调队列，不要排序 |
| 8 | **分不清「递增/递减」相对哪个方向** | ★ 一律看「老 → 新」（front→back / bottom→top），该方向**递减** → 「越老越大」|

## 六、容器取值前判空（通用纪律）

★ **“弹出/取元素前先判空”是必须养成的习惯，适用于所有标准容器。**

### 6.1 ⚠️ 这些操作都【不检查】

```cpp
deque<int> dq;       // 空
dq.front();          // ❌ UB
dq.back();           // ❌ UB
dq.pop_front();      // ❌ UB
dq.pop_back();       // ❌ UB
```

★ 标准容器为了性能，**取值类操作一律不检查**，空访问 = UB。

### 6.2 哪些要检查，哪些不要

| 操作 | 必须检查？ |
|---|---|
| `front()` / `back()` / `top()` | ✅ 必须 `!empty()` |
| `pop_front()` / `pop_back()` / `pop()` | ✅ 必须 `!empty()` |
| `push_back()` / `push()` | ❌ 不需要（往里加不涉及空） |
| `empty()` / `size()` | ❌ 不需要（就靠它俩查） |

### 6.3 ★ `!empty()` 必须放 `&&` 左边

```cpp
while (!dq.empty() && nums[dq.back()] <= nums[end])   // ✅ 左
while (nums[dq.back()] <= nums[end] && !dq.empty())   // ❌ 右 → 崩
```

★ **因为 `&&` 短路求值**：左边为假就立刻停，不再看右边。

→ **把判空永远放最左，当成脉肉记忆。**

### 6.4 何时可以省略

★ **只有当逻辑上能确定非空时**（如刚被 `while (!empty()` 保证过），才可以省。
**改代码后保证可能失效 —— 不确定就加。**

### 6.5 各容器对照

| 容器 | 危险操作 | 检查方式 |
|---|---|---|
| `vector` | `front()` `back()` `pop_back()` | `!empty()` |
| `deque` | 同上 + `pop_front()` | `!empty()` |
| `stack` | `top()` `pop()` | `!empty()` |
| `queue` / `priority_queue` | `front()` `top()` `pop()` | `!empty()` |
| `map` / `set` | `begin()->first`、`rbegin()` 解引用 | `!empty()` |
| `string` | `s[0]`、`s.back()` | `!empty()` |
| 原始数组 | `a[i]` | `i < 长度` |

### 6.6 与其他语言对比

| 语言 | 空容器取值 |
|---|---|
| **C++** | **UB（什么都不报，最危险）** |
| Java | 抛 `IndexOutOfBoundsException` |
| Python | 抛 `IndexError` |
| Rust | 返回 `Option`（类型系统强制处理） |

★ **C++ 是最不友好的 —— 它什么都不说，直接 UB。所以这个习惯在 C++ 里尤其重要。**

### ★ 底层视角：`stack` 到底是什么

- ★ **`stack` 不是独立容器，而是「适配器」**：`stack<int>` 默认底层是 `deque<int>`，只露出「顶进顶出」的接口
- ⚠️ 所以它**不能遍历、不能随机访问、没有 `clear()`** —— 这是**故意的**（用接口限制防误用）
  ★ 需要遍历时就用 `vector` 手动当栈：`push_back` / `back` / `pop_back`
  ★ 详见 `速查手册/C++-内存与调度-速查.md` 第 3.3 节。

### 6.7 心智模型

```text
push      = 往箱子里放          → 不用检查
empty     = 问箱子空不空        → 不用检查
front/back/top/pop = 从箱子里拿 → 必须先确认不是空的！
```

## 七、与「滑动窗口」的关系

★ **单调队列是滑窗家族的一个分支，但引入了新工具：**

```
滑动窗口
├── 状态可 O(1) 加减   → 3 / 209 / 567 / 438 / 1004 / 76
└── 状态需要「最值」   → 单调队列（239）
```

**判断标准**：如果你的窗口状态**不能靠「加一个/减一个」O(1) 维护**，就考虑单调队列。

## 八、LeetCode 155 案例（最小栈 · OOP 入门）

题目：设计一个栈，支持 O(1) 获取最小元素。

> ★ 本人独立完成（用 `stack`）。这是第一道「设计类 / OOP」题。

### 8.1 核心思想：辅助栈

★ **用一个辅助栈记录「每一步的最小值」。**

```text
主栈 st:     存所有元素
辅助栈 minst: 只在「新值 <= 当前最小值」时才 push
            → minst 从栈底到栈顶单调不增
```

- `getMin()` → `minst.top()`
- `pop()` → 如果弹出的值 == `minst.top()`，则 `minst` 也弹

★ **这就是「单调栈」的入门：用另一个栈维护「历史最值」，且保持单调性。**

### 8.2 代码

```cpp
class MinStack {
private:
    stack<int> st;
    stack<int> minst;

public:
    void push(int value) {
        st.push(value);
        if (minst.empty() || value <= minst.top()) {   // ★ 用 <=（处理相等值）
            minst.push(value);
        }
    }

    void pop() {
        if (st.top() == minst.top()) minst.pop();
        st.pop();
    }

    int top()    { return st.top(); }
    int getMin() { return minst.top(); }
};
```

### 8.3 ★ 两种写法对比

| | 只在更小时 push（本人） | 每次都 push 当前最小值 |
|---|---|---|
| `push` | 要判断 | `minst.push(min(val, minst.top()))` |
| `pop` | 要判断（弹出值 == 栈顶） | 两个栈直接弹 |
| 空间 | 小 | 大（= st 大小） |
| 相等值 | **必须用 `<=`** | 天然没问题 |

★ **用 `>` 而不是 `>=` 会出错**：相等值不 push，但 `pop` 时会把 `minst` 弹空。

### 8.4 陷阱

| # | 坑 | 正确做法 |
|---|---|---|
| 1 | `minst.top() >= value` 未先判空 | `!minst.empty() && ...` 或 `empty() || ...`（短路） |
| 2 | 相等值时用 `>` | 用 `>=` 或 `<=` |
| 3 | `stack` 没有 `clear()` | 需要就换 `vector`；155 不需要 |

## 九、LeetCode 739 案例（每日温度 · 纯单调栈）

题目：对每天，求「还要等几天才会更暖」。

> ★ 本人独立完成，一次通过。

### 9.1 代码

```cpp
class Solution {
public:
    vector<int> dailyTemperatures(vector<int>& temperatures) {
        int n = temperatures.size();
        vector<int> ans(n, 0);                  // 默认 0（没找到）
        stack<int> st;                           // 存下标
        for (int i = 0; i < n; i++) {
            while (!st.empty() && temperatures[st.top()] < temperatures[i]) {
                int j = st.top();
                st.pop();
                ans[j] = i - j;                  // 距离
            }
            st.push(i);
        }
        return ans;
    }
};
```

### 9.2 为什么栈内递减

```text
[75, 71, 69] + 新元素 72
→ 69 < 72 → 弹出（记答案）
→ 71 < 72 → 弹出（记答案）
→ 75 > 72 → 停
→ push(72) → [75, 72]   ← 仍然递减 ✓
```

★ **每次弹掉所有比新元素小的 → 剩下的都比新元素大 → 递减保持。**

### 9.3 ★ 单调栈 vs 单调队列（去掉一步）

| | 单调队列（239） | 单调栈（739） |
|---|---|---|
| 结构 | `deque` | `stack` |
| 位置 | 两头动 | 一头动 |
| ① 踢 | `while (...) dq.pop_back();` | `while (...) { 记答案; st.pop(); }` |
| ② 进 | `push_back(end)` | `push(i)` |
| ③ 弹过期 | `while (...) dq.pop_front();` | **没有** |
| ④ 取答案 | `nums[dq.front()]` | 在 ① 里填好 |

★ **单调栈 = 单调队列去掉「弹过期」+ 在踢的时候记答案。**

### 9.4 为什么单调栈不需要「弹过期」

- 单调队列：窗口在**移动**，元素会**滑出窗口** → 队首可能过期
- 单调栈：元素**永远在等答案**，没有时间限制，直到被弹出才结束

★ **「下一个更大元素」没有窗口概念 → 不需要过期机制。**

### ★ 底层视角：为什么这里用 `stack` 而不用递归

- 单调栈也可以写成**递归版**（“找右边第一个比我大的”天然递归）
- ⚠️ **但递归要压栈（每次调用一个栈帧）**：深递归会爆栈 / TLE
  ★ **迭代 + 显式 `stack` 就是「自己管栈帧」** → 可控、无爆栈风险
  ★ 底层原理见 `速查手册/C++-内存与调度-速查.md` 第 5.2 节。

### 9.5 ⚠️ 易混：739 vs 496

| | 每日温度（739） | 下一个更大元素 I（496） |
|---|---|---|
| 输入 | **一个**数组 | **两个**数组 `nums1`、`nums2` |
| 答案 | 距离（`i - j`） | **值**（下一个更大的那个数） |
| 输出长度 | = 输入长度 | = `nums1` 长度 |
| 需要哈希表 | ❌ | ✅（值→下一个更大值） |

★ **两题骨架相同，只改一行：**

```cpp

ans[j] = temperatures[i];          // 496 风格：要值
```

### 9.6 什么时候用哪个

| 题目问什么 | 用什么 |
|---|---|
| 滑动窗口内的最值 | **单调队列** |
| 某元素左/右边第一个更大/更小 | **单调栈** |

★ **判据：有没有「窗口滑动」？有 → 队列；没有，只是「方向性查找」→ 栈。**

## 十一、一句话总结

> ★ **「递增/递减」的方向：一律指「老 → 新」（队列 front→back、栈 bottom→top）→ 该方向递减（越老越大）。**

> ★ **单调队列是「滑动窗口 + 需要最值」的解法：用 `deque` 维护一个「值递减、下标递增」的序列，队首天然是最大值，过期就弹队首，新元素踢掉所有比它小的队尾元素。**
>
> **「踢」不是排序，而是「丢弃永远不可能成为答案的元素」—— 被踢的既比新元素小、又比新元素先过期。**
>
> **实现要点：存下标（不存值）、`!empty()` 判断、窗口满才输出。**
>
> ★ **单调栈是它的简化版：去掉「弹过期」，并在踢的时候把答案记给被踢的元素。**
>
> ```cpp
> // 单调栈骨架（就这么多）
> for (int i = 0; i < n; i++) {
>     while (!st.empty() && nums[st.top()] < nums[i]) {
>         ans[st.top()] = ...;   // ① 记答案
>         st.pop();               //    再踢
>     }
>     st.push(i);                 // ② 进栈
> }
> // ③ 栈里剩下的 = 没找到答案的（由初始化值兜底）
> ```
>
> **用途：「下一个更大/更小元素」类问题（739 / 496 / 84 / 42）。**

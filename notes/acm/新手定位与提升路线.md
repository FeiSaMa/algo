## 三、⚠️ 当前的主要问题：实现细节（不是算法）

### 3.1 ★ 实证：最近 30+ 题的卡点统计

★ **几乎全部卡在「实现」，而不是「算法」：**

| 类型 | 具体案例 |
|---|---|
| **下标 / 边界** | 航班预订漏 `-1`（越界 MLE）、二维区域和 `n = n_r`（行/列混）、二维区域和内层用 `m`、有序数组平方 `size_t` 回绕 |
| **循环 / 死循环** | 首末位置 `left = mid` 死循环、三数之和找到解不推进（MLE）、送货能力换天不重置累加器 |
| **对称手滑** | 三数之和 `left--` 应为 `right--`、合并区间 `<` 应为 `<=`、合并区间 `end = itv[1]` 缺 `max` |
| **哈希 API** | 两数之和先记后查读到自己、两数之和 `count(mp[k])` 套两层、和为 K 的子数组 `mp[0]=0` |
| **类型 / 溢出** | `int cur` 存前缀和、`pow(x,2)` |

★ **算法层面真正卡住的次数：很少**（基本都是「没想到某个技巧」，讲完就能立刻写出来）。

### 3.2 ★ 结论：不是「不会」，是「写不干净」

```
算法思维 = 跟上节奏了
实现细节 = 还在拖后腿
```

★ **这类问题的特点**：
- **不难**，但**频繁**
- 每次只花 5~20 分钟就能修
- **但在比赛里会直接决定成败**（一个越界 = 0 分）

### 3.3 ★ 对策：30 秒检查清单（已写入总复习）

```
□ 数组开多大？（n 还是 n+1）
□ 下标从 0 还是 1 开始？题目 1-based 要转吗？
□ 累积量会不会溢出 int？→ long long
□ 循环结束条件 < 还是 <=？
□ while 里每个分支都会让「状态前进」吗？（防死循环）
□ 空输入 / 单元素会怎样？
```

★ **从「下次注意」升级为「流程化检查」** —— 靠流程而不是靠记性。

## 四、⚠️ 自己诊断出的「下标思维」惯性

★ **自述：「总想用下标，然后自己卡自己」** —— 这是一个准确的自我诊断。

### 4.1 现象

```cpp
// 本能：
for (int i = 0; i < n; i++) { ... intervals[i][0] ... }

// 更自然：
for (auto& itv : intervals) { ... itv[0] ... }
```

### 4.2 代价

| 用下标 | 用元素 |
|---|---|
| `ans[ans.size() - 1]` | **`ans.back()`** |
| 要判断「是不是第一个」 | **`!ans.empty()`** |
| 容易 `i±1` 越界 | 无 |

★ **合并区间（56）：一开始想用 `start`/`end` 变量 + flag，换成 `ans.back()` 后完全不需要。**

### 4.3 ★ 判据（什么时候该用下标）

> **`i` 是不是算法语义的一部分？**
> - 是（滑窗的 `left`/`right`、55 的「能否到达 i」、DP）→ **用下标**
> - 否（只是「取最后一个」「遍历」）→ **用元素 / `back()` / 范围 for**

### 4.4 现状

★ **已有意识，但还不是本能**（56 里主动用了 `ans.back()`，说明在进步）。

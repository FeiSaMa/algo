## 〇、一句话总纲

★ **排序是「工具」，贪心是「思想」—— 很多题的解法 = 排序 + 贪心（+ 双指针）。**

```
排序的作用：让「该选谁」变得明确、可比、可顺序处理
贪心的作用：每步选当前最优，不回头
```

★ **贪心能否成立，取决于「局部最优 → 全局最优」是否成立**（必须验证，不能想当然）。

## 一、排序（工具）

### 1.1 三种基本写法

```cpp
#include <algorithm>

vector<int> v = {3, 1, 4, 1, 5};

sort(v.begin(), v.end());                      // 升序
sort(v.begin(), v.end(), greater<int>());      // 降序
sort(v.begin(), v.end(), [](int a, int b) {    // 自定义
    return a > b;
});
```

★ **`sort(first, last, comp)`**：
- `first` / `last`：**半开区间** `[first, last)`
- `comp(a, b)`：返回 `true` 表示「**a 应该排在 b 前面**」

### 1.2 ★ 比较器的语义

```cpp
sort(v.begin(), v.end(), [](int a, int b) {
    return a < b;      // 「a 该排在 b 前面」= 小的在前 = 升序
});
```

| 比较器 | 结果 |
|---|---|
| `return a < b;` | 升序 |
| `return a > b;` | 降序 |

★ **记忆：写「我想要谁排在前面」。**

### 1.3 ⚠️ 坑 1：比较器不能用 `<=` / `>=`

```cpp
sort(v.begin(), v.end(), [](int a, int b) {
    return a <= b;      // ❌ 违反严格弱序 → UB（可能崩溃）
});
```

★ **原因**：`sort` 要求 `comp(a, a) == false`（自己不能排自己前面）。`a <= a` 返回 `true` → 违反。

★ **铁律：比较器里只用 `<` 或 `>`。**

### 1.4 ⚠️ 坑 2：`vector` / `pair` 的默认比较是「字典序」

```cpp
vector<vector<int>> v = {{1,3}, {1,2}};
sort(v.begin(), v.end());       // 先比 [0]，再比 [1] → {{1,2},{1,3}}
```

★ **`pair` / `vector` / `tuple` 有默认字典序** —— 按元素依次比。

⚠️ **所以「按右端点排序」必须自己写比较器**（默认是按第一个元素）。

```cpp
sort(intervals.begin(), intervals.end(), [](auto& a, auto& b) {
    return a[1] < b[1];      // 按右端点
});
```

### 1.5 多关键字排序

```cpp
sort(v.begin(), v.end(), [](auto& a, auto& b) {
    if (a.first != b.first) return a.first < b.first;   // ★ 第一关键字
    return a.second > b.second;                          // 第二关键字
});
```

★ **第一个条件用 `!=` 判断**（不能写成 `a.first < b.first || a.second > b.second`）。

### 1.6 稳定性

```cpp
stable_sort(v.begin(), v.end(), comp);   // 稳定：相等元素保持原相对顺序
```

★ `sort` **不稳定**；`stable_sort` 稳定但更慢。**通常「一次写好多关键字」比用 `stable_sort` 好。**

### 1.7 ★ 排序的用途（不只是「排好序」）

| 排序后能做什么 | 例 |
|---|---|
| **让贪心「有据可依」** | 区间按右端点 / 左端点排 |
| 相邻元素可比较 | 217 判重（排序后看相邻）|
| 配合双指针 | 分发饼干（455） |
| 二分的前提 | 二分查找要求有序 |
| 去重 | `sort` + `unique` |

★ **核心认知：排序是为别的算法「铺路」** —— 很多题 = **排序 + X**。

## 二、贪心（思想）

### 2.1 定义

★ **每步都选「当前看起来最优」的，不回头、不反悔。**

```
贪心 = 局部最优 → 希望推出全局最优
```

| 思想 | 特点 |
|---|---|
| 暴力 | 尝试所有可能 |
| **贪心** | **每步只看眼前最优，一次决定，不回头** |
| DP | 记录所有子问题解，从多条路里选 |

### 2.2 ⚠️ 贪心「可能错」—— 必须验证

★ **只在「局部最优 → 全局最优」成立时才对。**

**经典反例（凑零钱）**：面额 `[1,3,4]` 凑 6

```
贪心（每次拿最大）：4 + 1 + 1 = 3 枚
最优：            3 + 3     = 2 枚   ← 贪心错
```

★ **验证方法**：
1. **交换论证**：证明「任何最优解都能改造成含贪心选择的最优解」
2. **举反例**：构造一个贪心错、最优对的例子

★ **竞赛实用做法：先猜贪心，构造反例试；试不出来就先信它。**

### 2.3 ★ 用贪心前必问

> **我这一步的选择，会不会害了后面？**
> - 不会 → 贪心可能成立（要验证）
> - 会 → 不能用贪心

## 三、★ 贪心的两种形态（本板块核心）

### 形态 A：排序型（选子集类）

★ **排序让「该选谁」明确，然后顺序扫描 / 双指针。**

| 题 | 排序键 | 贪心策略 |
|---|---|---|
| **分发饼干（455）** | 两数组升序 | 最小饼干喂最小胃口 |
| **无重叠区间（435）** | **右端点** | 选「结束最早」的，给后面留空间 |
| **合并区间（56）** | **左端点** | 按起点顺序缝合 |

★ **排序键的选择（最重要的一步）**：

| 题目目标 | 排序键 | 原因 |
|---|---|---|
| **选最多 / 最少（腾空间）** | **右端点** | 结束早 → 后面可选的更多 |
| **合并 / 覆盖 / 按顺序处理** | **左端点** | 按起点才能顺序连接 |

⚠️ **排序键选错 → 全盘错**（见 §五 反例）。

### 形态 B：扫描型（可达性 / 累积类）

★ **顺序固定，不排序；维护一个「状态」边走边更新。**

| 题 | 状态 | 更新方式 |
|---|---|---|
| **跳跃游戏（55）** | `reach`（最远可达下标）| `reach = max(reach, i + nums[i])`（仅当 `i <= reach`）|

★ **55 不能排序** —— 跳跃顺序是固定的，排序会破坏结构。

### 3.1 两种形态对比

| | 排序型 | 扫描型 |
|---|---|---|
| 排序 | ✅ 必须 | ❌ 不能（顺序固定）|
| 代表 | 455 / 435 / 56 | 55（及 45）|
| 关键 | **排序键的选择** | **状态的定义与更新** |

## 四、案例

### 4.1 分发饼干（455）（排序 + 双指针）

```cpp
int findContentChildren(vector<int>& g, vector<int>& s) {
    sort(g.begin(), g.end());
    sort(s.begin(), s.end());
    int i = 0, j = 0, cnt = 0;
    while (i < (int)g.size() && j < (int)s.size()) {
        if (g[i] <= s[j]) { cnt++; i++; j++; }   // 喂饱：都前进
        else j++;                                 // 喂不饱：换大饼干
    }
    return cnt;
}
```

★ **贪心策略：最小的够用饼干喂最小胃口** —— 不浪费大饼干。
★ **正确性（交换论证）**：若最优解用大饼干喂小胃口、小饼干喂大胃口，交换后喂饱数不变 → 不劣。

### 4.2 无重叠区间（435）（按右端点）

```cpp
int eraseOverlapIntervals(vector<vector<int>>& intervals) {
    sort(intervals.begin(), intervals.end(), [](auto& a, auto& b) {
        return a[1] < b[1];                          // ★ 按右端点
    });
    int keep = 0;
    int lastEnd = INT_MIN;
    for (auto& itv : intervals) {
        if (itv[0] >= lastEnd) {                     // ★ >= （端点相接不算重叠）
            keep++;
            lastEnd = itv[1];
        }
    }
    return (int)intervals.size() - keep;             // 移除数 = 总数 - 保留
}
```

★ **「移除最少」= 「保留最多」** —— 换个角度想更简单。

### 4.3 合并区间（56）（按左端点 + `ans.back()`）

```cpp
vector<vector<int>> merge(vector<vector<int>>& intervals) {
    sort(intervals.begin(), intervals.end(), [](auto& a, auto& b) {
        return a[0] < b[0];                          // ★ 按左端点
    });
    vector<vector<int>> ans;
    for (auto& itv : intervals) {
        if (!ans.empty() && itv[0] <= ans.back()[1]) {    // ★ <= （端点相接要合并）
            ans.back()[1] = max(ans.back()[1], itv[1]);   // ★ max！不能直接赋值
        } else {
            ans.push_back(itv);
        }
    }
    return ans;
}
```

★ **`ans.back()` 写法**：每个区间「并入最后一个」或「成为新的最后一个」→ **不需要「最后补一句」**。
★ **`max` 必须**：否则 `[1,10]` 遇到 `[2,3]` 会把 end 缩小成 3。

### 4.4 跳跃游戏（55）（扫描型贪心）

```cpp
bool canJump(vector<int>& nums) {
    int n = nums.size();
    int reach = 0;
    for (int i = 0; i < n; i++) {
        if (i > reach) return false;                 // 到不了 i
        reach = max(reach, i + nums[i]);
        if (reach >= n - 1) return true;             // 提前返回
    }
    return true;
}
```

★ **关键判断 `i <= reach`（能到 i 才更新 reach）** —— 从到不了的位置继续跳是无意义的。

## 五、⚠️ 区间贪心的「排序键」反例（核心认知）

★ **435 为什么必须按右端点，不能按左端点？**

```
intervals = [[1,100], [2,3], [4,5], [6,7]]

按左端点排：[[1,100], [2,3], [4,5], [6,7]]
  → 选 [1,100] 后，后面全被压住 → 保留 1 个 ❌

按右端点排：[[2,3], [4,5], [6,7], [1,100]]
  → 选 [2,3],[4,5],[6,7] → 保留 3 个 ✓
```

★ **本质：「结束早」= 给后面留的空间大** —— 贪心要「尽早腾出位置」。

★ **而 56 必须按左端点**：要顺序「缝合」区间，按起点才能连成链。

#### ★ 两题理由的精确对比（本人曾表述不准）

⚠️ **易错说法**：「合并区间按左端点，因为越早开始越容易包含其他区间」—— **这是错的**（包含关系不是关键）。

★ **正确理由**：

| | 目标 | 排序键 | 真正理由 |
|---|---|---|---|
| **无重叠区间** | **腾空间**（选最多）| 右端点 | 看「谁先**结束**」→ 结束早的给后面留得多 |
| **合并区间** | **顺序缝合**（把相连的并成一段）| 左端点 | 看「谁先**开始**」→ 才能逐个判断「能不能接上当前段」|

★ **一句话：**
- **选子集** → 关心「结束」→ 右端点
- **连成链** → 关心「开始」→ 左端点

★ **如果不按左端点合并会怎样**：区间乱序时，`ans.back()` 无法代表「当前正在缝合的段」→ 漏合并或错合并。

## 五·补、★ 区间问题的三大模型（统一视角）

★ **区间题不是三个互不相关的套路，而是同一个「按右端点排序」的贪心家族的三个成员。**

| 模型 | 题目 | 问什么 | 排序键 | 状态 | 判定 |
|---|---|---|---|---|---|
| **选最多不重叠** | 435 无重叠区间 | 最多能选几个区间？ | 右端点 | `lastEnd` | `start >= lastEnd` → 可选 |
| **选最少点覆盖** | 452 引爆气球 | 最少几个点能砸中所有区间？ | 右端点 | `lastEnd` | `start > lastEnd` → 需新点 |
| **合并成连通段** | 56 合并区间 | 合并后剩几段？ | **左端点** | `ans.back()` | `start <= back.end` → 合并 |

### ★ 5.补.1 「区间选点」模型（452 的本质）

★ **452 等价于这个经典问题：**
```
在数轴上选最少的点，使每个区间至少包含一个点
```

★ **贪心：按右端点排序，每次把点放在「当前未覆盖区间的右端点」。**

```
[1,6] [2,8] [7,12] [10,16]

① 点放 6 → 覆盖 [1,6] 和 [2,8]（6 ∈ [1,6] ✓、6 ∈ [2,8] ✓）
② [7,12] 不含 6 → 新点放 12 → 覆盖 [7,12] 和 [10,16]
→ 2 个点 ✓
```

★ **为什么放在「右端点」最省**：
```
第一个气球的 end = 所有气球中「最早结束」的
→ 任何能射到第一只气球的箭，都必须落在 [start₁, end₁] 里
→ 放在 end₁（最靠右）能覆盖尽可能多的后续气球
→ 后续气球右端都 >= end₁
```

### ★ 5.补.2 452 的两种等价写法

**写法 A（标准 · O(1) 空间 · 按右端点）**
```cpp
sort(points, by end);
int arrows = 1; int lastEnd = points[0][1];
for (i = 1..n-1)
    if (points[i][0] > lastEnd) { arrows++; lastEnd = points[i][1]; }
```

**写法 B（本人思考 · 按左端点 + 求交集）**
```cpp
sort(points, by start);
维护当前组的【公共交集】[max(左), min(右)]
若新区间左端 > 交集右端 → 交集断 → 新箭
箭头数 = 交集个数
```

★ **两者等价！** 因为：
```
按左端点排时，「交集右端」 = min(组内所有 end)
—— 这正好就是按右端点排时的 lastEnd
→ 所以「左端点排 + 只维护 min(end)」 = 「右端点排 + lastEnd」
```

⚠️ **本人踩坑（452）**：用 `vector<vector<int>>` 存整个交集 → 每步拷贝 + 动态扩容 + 按值遍历 → **105ms / beat 9%**。
★ **修法：左端点根本不用维护，只存 `lastEnd`（int）→ O(1) 空间。**

★★ **教训：「能用 O(1) 变量就不开容器」** —— 容器有分配/拷贝/缓存不友好的代价。

### ★ 5.补.3 端点相接：三个题的符号差异

| 题 | 端点相接算同一组/重叠吗 | 判定符号 |
|---|---|---|
| 435 无重叠 | ❌ 不算（可共存）| `start >= lastEnd` |
| **452 引爆** | ✅ **算**（一支箭能穿两个）| **`start > lastEnd` 才需要新箭** |
| 56 合并 | ✅ 算（要合并）| `start <= back.end` |

★ **452 与 435 差一个符号，只因一个问「能不能共存」、一个问「要不要新箭」。**

## 六、⚠️ 区间「重叠」的判定（易混）

| 题 | 判定 | 端点相接算重叠吗 |
|---|---|---|
| **435**（求不重叠） | `itv[0] >= lastEnd` → 不重叠 | ❌ **不算**（可共存）|
| **56**（要合并） | `itv[0] <= back()[1]` → 重叠 | ✅ **算**（要合并成一段）|

★ **两者逻辑对称**：
- 435 问「**能不能共存**」→ `[1,4]` 和 `[4,5]` 能 → `>=`
- 56 问「**要不要合并**」→ `[1,4]` 和 `[4,5]` 要 → `<=`

⚠️ **本人踩坑（56）**：写成 `<` 而不是 `<=` → 端点相接的区间没合并。

## 七、★ 「下标思维」vs「元素思维」（本人短板）

⚠️ **本人自述：总想用下标，然后自己卡自己。**

| 用下标 | 用元素 / 迭代器 |
|---|---|
| 要维护 `i`、算边界 | 直接拿元素 |
| `ans[ans.size()-1]` | **`ans.back()`** |
| 判断「是不是第一个」 | **`!ans.empty()`** |
| 容易 `i±1` 越界 | 无 |

### 7.1 三个习惯

```cpp
for (auto& itv : intervals) { ... }     // ✅ 不需要下标时用范围 for
ans.back()                               // ✅ 最后一个
if (!ans.empty())                        // ✅ 判空
```

### 7.2 ★ 什么时候「必须」用下标

| 场景 | 例 |
|---|---|
| 下标是算法语义的一部分 | 滑窗（`left`/`right`）、55（`i` 是「能否到达的位置」）|
| 需要 `i-1` / `i+1` | DP、前缀和 |
| 要返回索引 | Two Sum |
| 二分 | `left`/`mid`/`right` |

★ **判据：`i` 是不是算法语义的一部分？是 → 用；否 → 用元素。**

★ **本人已做到的例子**：56 里主动用了 `ans.back()` 和 `!ans.empty()`。

## 八、⚠️ 避坑清单

| # | 坑 | 正确做法 |
|---|---|---|
| 1 | 比较器用 `<=` / `>=` | 只用 `<` / `>`（严格弱序）|
| 2 | 以为 `vector<int>` 默认按右端点排 | 默认是**字典序**（先 `[0]`），要自定义 |
| 3 | **区间贪心的排序键选错** | 「腾空间」→ 右端点；「合并/顺序」→ 左端点 |
| 4 | 56 用 `<` 判重叠 | 端点相接要合并 → **`<=`** |
| 5 | 56 合并时直接 `end = itv[1]` | 必须 **`max(end, itv[1])`**（否则区间被缩小）|
| 6 | 56 用 `start/end` 变量 + 忘了最后 flush | 用 **`ans.back()`** 写法，天然完整 |
| 7 | 55 写成 `i < reach` | **`i <= reach`**（`i == reach` 能踩到）|
| 8 | 贪心不验证就用 | 先想反例 / 交换论证 |
| 9 | 空容器访问 `v[0]` | 先判空（`!v.empty()`）|

## 十、一句话总结

> ★ **排序是工具，贪心是思想 —— 很多题 = 排序 + 贪心（+ 双指针）。**
>
> ★ **贪心的两种形态**：
> - **排序型**（435 / 56 / 455）：排序键的选择是**第一决策**
>   - 「腾空间 / 选最多」→ **右端点**
>   - 「合并 / 按顺序」→ **左端点**
> - **扫描型**（55）：不排序，维护状态（`reach`）边走边更新
>
> ★ **贪心必须验证**（反例 / 交换论证）—— 局部最优不一定推得出全局最优。
>
> ★ **比较器只用 `<` / `>`**（严格弱序），`vector` / `pair` 默认是字典序。
>
> ★ **少用下标**：不需要 `i` 时用范围 for / `back()` / `front()` / `empty()`。

## 一、★ 信号 → 板块（先背这张！）

★ **看到题里的「信号词」，直接定位板块。**

| 题目信号 | 板块 |
|---|---|
| 连续子数组/子串 + 最长/最短 | **滑动窗口** |
| **「之前见过吗」「出现过几次」** | **哈希表** |
| 「值 → 位置 / 答案」映射 | **哈希表** |
| 一 key 对多个结果（分组/分桶）| **哈希表 + `map<K, vector<V>>`** |
| 多次区间求和 | **前缀和** |
| 多次区间加值 | **差分** |
| 「多少个子数组满足和 = k」（元素**可为负**）| **前缀和 + 哈希** ⚠️ 不能用滑窗（无单调性）|

| 答案有单调性 /「最小化最大值」| **二分答案 + 贪心** |

## 二、★ 核心模板速查（遮住自查）

### 2.1 滑动窗口（可变长）

```cpp
int left = 0;
for (int right = 0; right < n; right++) {
    // ① 扩张：把 nums[right] 纳入窗口
    while (/* 窗口不满足条件 */) {
        // ② 收缩：把 nums[left] 移出
        left++;
    }
    // ③ 更新答案
}
```

★ **判断能否用滑窗：① 连续子区间 ② 状态可 O(1) 加减 ③ 有单调性**

### 2.2 哈希表（先查后记）

```cpp
unordered_map<K, V> mp;
for (...) {
    if (mp.count(需要的东西)) { ... }   // ① 查（消费者）
    mp[当前元素] = 相关值;               // ② 记（生产者）
}
```

★ **判存在用 `count` / `find`**（`mp[k]` 会偷偷创建）
★ **`insert().second` 可一次完成查+记**（仅当查插同键）

### 2.3 前缀和 / 差分

```cpp
// 前缀和：pre[i] = 前 i 个之和（n+1 个）
for (int i = 0; i < n; i++) pre[i + 1] = pre[i] + nums[i];
// sum(nums[l..r]) = pre[r + 1] - pre[l]

// 差分：d[i] = nums[i] - nums[i-1]（n+1 个）
d[l] += v;  d[r + 1] -= v;               // 区间 [l,r] +v
for (int i = 0; i < n; i++) { cur += d[i]; ans[i] = cur; }
```

★ **二维**：`pre[i][j] = pre[i-1][j] + pre[i][j-1] - pre[i-1][j-1] + m[i-1][j-1]`
★ **查询**：`pre[r2+1][c2+1] - pre[r1][c2+1] - pre[r2+1][c1] + pre[r1][c1]`

### 2.4 二分（统一下界模板）

```cpp
int left = 0, right = n;              // 半开 [left, right)
while (left < right) {
    int mid = left + (right - left) / 2;
    if (条件(mid)) right = mid;        // ★ 只用 right = mid
    else left = mid + 1;
}
return left;
```

★ **lower_bound**：`nums[mid] >= target`；**upper_bound**：`nums[mid] > target`
★ **二分答案**：`条件 = can(mid)`

### 2.5 排序

```cpp
sort(v.begin(), v.end());
sort(v.begin(), v.end(), [](auto& a, auto& b) { return a[1] < b[1]; });
```

### 2.6 对撞双指针

```cpp
int left = 0, right = n - 1;
while (left < right) {
    // 根据当前状态决定动哪边
    if (条件) left++; else right--;
}
```

## 三、★ 排序键 / 移动方向的「判据表」（最容易错）

### 3.1 区间贪心的排序键

| 目标 | 排序键 |
|---|---|
| 选最多 / 腾空间 | **右端点**（无重叠区间）|
| 合并 / 按顺序处理 | **左端点**（合并区间）|

### 3.2 对撞的移动判据

| 场景 | 动哪边 |
|---|---|
| 和太小 | `left++`（增大）|
| 和太大 | `right--`（减小）|
| **容器面积** | **移矮的那端** |

### 3.3 端点相接算不算重叠

| 题 | 端点相接 |
|---|---|
| 无重叠区间 | 不算（`>=`）|
| 合并区间 | 算（`<=`）|

### 3.4 ★ 三个「为什么」的精确表述

| 问题 | 精确回答 |
|---|---|
| **无重叠为什么按右端点** | 选子集 → 关心「谁先**结束**」→ 结束早的给后面留空间 |
| **合并为什么按左端点** | 连成链 → 关心「谁先**开始**」→ 才能顺序判断能否接上 |
| **盛水为什么移矮的** | 宽度只会减小 → 移高的 `min` 不变或更小 → 面积只会变小；移矮的 `min` 可能变大 |

## 四、★ 我的踩坑总汇（按类型）

### 类型 A：下标 / 边界（最高频！）

| 坑 | 题 | 修法 |
|---|---|---|
| **1-based 漏转 0-based** | 航班预订 | 差分：`d[first-1]` / `d[last]` |
| **行/列（m/n）搞混** | 二维区域和 | 明写 `rows` / `cols` |
| **拍平公式乘了行数** | 二维区域和 | `row * 【列数】 + col` |
| **`size_t - 1` 回绕** | 有序数组平方、多次 | 用 `int` 下标 |
| **空数组访问 `nums[0]`** | 连续序列、合并区间 | 先判空 / 用范围 for |
| **数组开 `n` 而非 `n+1`** | 前缀和 / 差分全场 | 前缀和留 `pre[0]=0`，差分防 `d[r+1]` |
| **`dp[0][0]` 前没判 `n == 0`（★ 第 3 次）** | 买卖股票 II | 建表前先 `if (n == 0) return 0;` |
| **`dp[0][0]` 前没判 `n == 0`（★ 第 4 次）** | 含冷冻期 309 | 同上（122 改完下一题又忘了 → 已写进 §6.1 首行）|
| **计数型维度的 `k=0` 层没填** | 买卖股票 III | `k` 循环从 1 开始前，先显式填 `dp[i][0][0]=0`、`dp[i][1][0]=INT_MIN/2` |
| **参数化数组长度开 `k` 而非 `k+1`** | 买卖股票 IV | 笔数取值是 `0..k` 共 `k+1` 个 |

### 类型 B：循环 / 死循环

| 坑 | 题 | 修法 |
|---|---|---|
| **`left = mid` + 向下取整 → 死循环** | 首末位置 | 只用 `right = mid`；或向上取整 |
| **找到答案不推进指针 → 死循环** | 三数之和 | `left++; right--;` |
| **换天不重置累加器** | 送货能力 | `cur = w`（不是清零）|

### 类型 C：哈希表

| 坑 | 题 | 修法 |
|---|---|---|
| **先记后查 → 读到自己** | 两数之和 | **先查后记** |
| **`mp.count(mp[k])` 套两层** | 两数之和 | `count(键)` 问存在；`mp[键]` 取值 |
| **用 `mp[k]` 判断存在** | — | 用 `count` / `find` |
| **`insert` 想覆盖** | 存在重复元素II | 用 `mp[k] = v` |
| **`mp[0] = 0`（应为 1）** | 和为K的子数组 | 空区间前缀和 0 计数 1 |
| **预存 pre 数组 + 哈希混用** | 和为K的子数组 | 用 `cur` 增量版 |
| **一 key 多值用 int** | 异位词分组 | `map<K, vector<V>>` |

### 类型 D：类型 / 溢出

| 坑 | 题 | 修法 |
|---|---|---|
| **`char` 计数溢出** | 字符串排列 | 用 `int` |
| **`int cur` 存前缀和** | 和为K、拼车 | `long long` |
| **`mid = (l+r)/2` 溢出** | 二分 | `left + (right-left)/2` |
| **`pow(x,2)`** | 有序数组平方 | `x * x` |

### 类型 E：对称操作写反

| 坑 | 题 | 修法 |
|---|---|---|
| **`left--` 应为 `right--`** | 三数之和 | left 配 `left++`，right 配 `right--` |
| **`<` 应为 `<=`** | 合并区间 | 端点相接要合并 |
| **`itv[1]` 应为 `max(...)`** | 合并区间 | 否则区间被缩小 |

### 类型 G：语义混乱

★ **核心特征：同一个位置/变量承担两种语义。**

| 坑 | 题 | 修法 |
|---|---|---|
| **把 `mat` 的 `1` 改成 `0` 当 visited** | 腐烂的橘子 542 | `0` 本义是「源点」，改用单独 `visited` 或距离值 |
| **dp 格子的值当成「标志位」**（想用 `dp[i][2]` 存「是否冻结」的 0/1）| 含冷冻期 309 | ★ dp 格子必须存**目标值**，「身份」由**下标**承载 |

★★ **统一自检问句**：「这个格子/变量存的是**目标值**吗？」
答不上来 → 状态定义还没落地，別写代码。

## 六、★ 我的短板与针对性提醒

★ **自我诊断：分析力 > 实现力。算法想得通，常栽在实现细节。**

| 短板 | 表现 | 对策 |
|---|---|---|
| **下标思维** | 总想维护 `i`，反被 `±1` 卡住 | 不需要 `i` 时用范围 for / `back()` / `empty()` |
| **边界** | 差一、闭/半开混用 | 统一半开；先写 `n`/`n+1` 的约定 |
| **类型** | `int` 存大数、`size_t` 回绕 | 前缀和/差分一律 `long long`；下标用 `int` |
| **对称手滑** | `left--` vs `right--` | 写前默念「自己比自己旁边，自己走」|

### 6.1 每次写题前的 30 秒检查清单

**通用（任何题）**
```
□ 【第一行】空输入 / 单元素会怎样？ → 先写 if (n == 0) return ...;  ★ 连错 4 次
□ 数组开多大？（n 还是 n+1；计数维度是 k 还是 k+1）
□ 下标从 0 还是 1 开始？题目 1-based 要转吗？
□ 累积量会不会溢出 int？→ long long
□ 循环结束条件 < 还是 <=？
□ while 里每个分支都会让「状态前进」吗？（防死循环）
```

**哈希表专用**
```
□ 用 mp[k] 判断存在了吗？→ 改用 count / find
□ 想用 insert().second 合一步？→ 先问：查的键 == 插的键 吗？
     是（217 判重）→ 可以合一
     否（两数之和、和为K）→ 老老实实两步
□ 「前缀和 + 哈希」类：mp[0] = 1 写了吗？（空区间登记，漏了漏掉所有从头开始的答案）
```

**区间/排序类**
```
□ 排序键选对了吗？
     选子集 / 腾空间 → 右端点
     合并 / 连成链 → 左端点
□ 端点相接算不算重叠？
     无重叠区间 → 不算（>=）
     合并区间 → 算（<=）
```

**扫描型贪心（55 / 121）**
```
□ 先更新「状态」再算答案了吗？（minPrice / reach 在前，ans 在后）
□ 答案初值取 0 还是 INT_MIN？允许「不操作」→ 取 0
□ 成立的前提还成立吗？（121 前提：只允许一次交易）
```

**状态机 DP（122 起）**
```
□ 状态是「互斥身份」吗？（空仓 / 持仓，不是「前 i 个」，也不是「买/卖」动作）
□ 限制类型是什么？ 成本 → 不改状态数 / 时机 → 加状态 / 次数 → 加维度
□ 非法状态初值给了负无穷吗？（给 0 会让非法路径污染答案；用 INT_MIN/2）
□ 终态返回的是「目标身份」那个状态吗？（不是 max(所有状态)）
□ 每个状态的**来源数**是几？ 1 个用 `=`，≥2 个用 `max`
□ 计数维度 `k`：只在【买入】时 `k-1→k`；`k=0` 层是边界，显式填且不进循环
□ 参数化维度（`k` 由输入给）：先做退化检查（`k >= n/2` → 122 贪心），且在建表之前
```

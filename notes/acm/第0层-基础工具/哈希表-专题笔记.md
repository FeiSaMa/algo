## 〇、一句话总纲

★ **哈希表 = 「下标可以是任意类型」的数组 —— 把「值」映射到「另一个值 / 位置」，平均 O(1) 查询。**

它解决的问题是：**「我需要快速查『某个东西出现过没有 / 它在哪 / 它出现了几次』」** —— 数组下标放不下（如字符串、大整数）时，就用哈希表。

★ **核心套路：一次遍历，边走边把「已经看过的东西」记进哈希表（空间换时间）。**

## 一、为什么需要它（问题的来源）

### 1.1 数组下标的天花板

最朴素的「哈希」你早就用过 —— 字符计数：

```cpp
int cnt[128];
cnt[c]++;          // 下标 = 字符的 ASCII 值（小整数）
```

- ✅ 下标是 0~127 的小整数 → 数组够用
- ❌ 下标是**字符串、大整数、任意值**呢？→ 数组做不到
- ❌ 值域极大（如 `1e9`）→ 数组开不出来

★ **数组下标必须是「非负小整数」；哈希表把这个限制打破了。**

| | 数组 | 哈希表 |
|---|---|---|
| 下标类型 | 非负小整数 | 任意（int / string / char / pair...） |
| 查询 | O(1) | 平均 O(1) |
| 内存 | 按**最大下标**分配 | 按**实际存的元素数**分配 |
| 遍历顺序 | 按下标 | 无序（`unordered_*`） |

### 1.2 降维打击的经典场景

看本人在 1. Two Sum 的暴力：

```cpp
// 对每个 x，再扫一遍后面找 target - x        O(n²)
```

★ **暴力慢，是因为「查一个数在不在」要扫一遍。哈希表把这个「查」变成 O(1) → 整体 O(n)。**

★ **这就是「空间换时间」：多花 O(n) 的内存，省下 O(n²) 的时间。**

### ★ 底层视角：为什么哈希能 O(1)（而不是只有 O(log n)）

- **哈希表**：`key → hash → % 桶数` → **直接算出位置**（一步到位）→ 平均 O(1)
- **红黑树（map/set）**：每次比较排除一半 → O(log n)
  ★ **本质上是用「内存换时间」**：哈希表要预先开桶数组；且链表节点分散（cache 不友好）。
  ★ 对 Two Sum：n=10⁴ 时 O(n) 与 O(n log n) 都过，但哈希常数小、写法直白。

## 二、Python 直觉：你天天在用哈希表

★ **Python 的 `dict` 和 `set` 就是哈希表。** 算法里「不会哈希表」，其实只是不知道 C++ 里它叫什么。

```python
# 统计词频
freq = {}
for c in s:
    freq[c] = freq.get(c, 0) + 1

# 查某个东西在不在
if x in seen:            # seen 是 set
    ...
```

★ **你的 Python 直觉 90% 直接迁移**，只需记住两条 C++ 特有的：
1. 名字带 `unordered_` 前缀（不加就是红黑树）
2. `mp[k]` 会自动创建（判断「存在吗」请用 `count` / `find`）

## 三、C++ 的四个工具

C++ 的哈希工具按「存什么」分两类，按「有序/无序」分两族：

| 只存「键」（集合） | 存「键→值」（映射） | 有序吗 | 底层 | 查找 |
|---|---|---|---|---|
| `set` | `map` | ✅ 有序（按键升序） | **红黑树** | O(log n) |
| `unordered_set` | `unordered_map` | ❌ 无序 | **哈希表** | O(1) 平均 |

★ **只有名字带 `unordered_` 的才是真正的哈希表。** `set` / `map` 是红黑树（有序但慢一点）。

### 怎么选

| 你要什么 | 用哪个 |
|---|---|
| 只查「存在吗」 | `unordered_set` |
| 查「值 → 位置 / 计数」 | `unordered_map` |
| 需要**有序**遍历 / 找前驱后继 | `set` / `map` |
| 怕被卡哈希（竞赛防 hack） | `set` / `map`（稳定 O(log n)） |

★ **新手默认用 `unordered_set` / `unordered_map`。**

⚠️ **LeetCode 上 `unordered_map` 有被「哈希碰撞攻击」卡成 O(n²) 的可能**，但新手阶段不用管，正常题用 `unordered_*` 即可。

## 四、六个操作（覆盖 95% 的题）

```cpp
#include <unordered_map>
#include <unordered_set>

// ===== unordered_map（键 → 值） =====
unordered_map<int,int> mp;

mp[key] = val;                     // ① 赋值/覆盖（key 不存在会自动创建！）
mp[key]++;                         // ② 计数（不存在的 key 自动初始化为 0 再 ++）
int v = mp[key];                   // ③ 取值（⚠️ key 不存在会自动插入 0！）
mp.count(key);                     // ④ 存在吗？返回 0 / 1（不插入，安全）
mp.find(key) != mp.end();          // ⑤ 存在吗？（等价写法）
mp.erase(key);                     // ⑥ 删除
mp.size();                         //    元素个数
for (auto& [k, v] : mp) { ... }    //    遍历（C++17 结构化绑定）

// ===== unordered_set（只存键） =====
unordered_set<int> st;
st.insert(x);                      // 插入
st.count(x);                       // 存在吗（0 / 1）
st.erase(x);                       // 删除
```

### ⚠️ 最大的坑：`mp[key]` 会「偷偷创建」

```cpp
if (mp[x] == 0) { ... }    // ❌ 危险：x 不存在时，这句会先插入一个 x=0
                           //    之后 mp.size() 变了，还可能掩盖 bug
if (mp.count(x)) { ... }   // ✅ 只想判断存在，用 count 或 find
```

★ **`[]` 是「读 / 写」运算符，没有只读版本；只想问「在不在」，永远用 `count()` 或 `find()`。**

### ★ 底层视角：`mp[k]` 的「自动创建」从哪来

- 哈希表底层是「桶数组 + 链表」，`mp[k]` = 「查找 k，**没有就插入一个默认值**」
- 因为 `[]` 要支持 `mp[k] = v`（写入），所以它**没有只读语义** → 查不到就得造一个
- `count()` / `find()` 是**只读查询**，不改容器
  ★ **代价**：`mp[k]` 多一次「可能插入」的分支；`count` 只是查。所以**判断存在用 `count` 又快又安全**。
  ★ 完整内存布局（桶/rehash/reserve）见 `速查手册/C++-内存与调度-速查.md` 第 3.4 节。

### 4.1 ★ `insert` 的返回值：`pair<迭代器, bool>`

★ **`insert` 不返回 `bool`，而是返回一个 `pair`（二元组）—— 因为调用者常需要两个信息：「插进去了吗」+「那个元素在哪」。**

```cpp
unordered_set<int> st;

// 写法一：auto 接住（推荐）
auto res = st.insert(x);
// res.first  → 迭代器，指向那个元素（无论新插的还是本来就有的）
// res.second → bool，true = 真的插进去了；false = 本来就有

// 写法二：结构化绑定（C++17，更清爽）
auto [it, ok] = st.insert(x);
if (!ok) { /* x 本来就在 */ }
```

★ **`pair` 就是「把两个值打包成一个」的模板**，用 `.first` / `.second` 访问：

```cpp
pair<int,string> p = {1, "one"};
p.first;    // 1
p.second;   // "one"
```

### 4.2 ★ 用法一：一次查找完成「查 + 记」（推荐）

★ **`insert` 是「原子」的：先判在不在，在就不插。** 所以 `count` + `insert` 两步可以合成一步：

```cpp
// 原版（两次哈希查找）
if (st.count(x)) return true;    // 查找①
st.insert(x);                     // 查找②（插入也要先找位置）

// 合并（一次查找）★
if (!st.insert(x).second) return true;   // .second == false 即「本来就有」
```

★ **本题（217）用的就是这个：**.second 为 false 说明重复。

### 4.3 ⚠️ 用法二：`map` 的 `insert` **不覆盖**！

```cpp
unordered_map<int,int> mp;
mp.insert({1, 100});                 // 表里没有 1 → 插入成功 {1:100}, ok=true
mp.insert({1, 999});                 // 表里已有 1 → 【不覆盖】！保留 {1:100}, ok=false
```

| 写法 | 键已存在时 |
|---|---|
| `mp.insert({k, v})` | ❌ **不覆盖**，保留旧值，返回 `ok=false` |
| `mp[k] = v` | ✅ **覆盖**成新值 |
| `mp.insert_or_assign(k, v)`（C++17）| ✅ 覆盖 |

⚠️ **想要「更新成最新值」时，必须用 `mp[k] = v`，不能用 `insert`** —— 否则旧值会残留在表里，逻辑静默出错。（219 要「覆盖成最新下标」就是这类）。

### 4.4 ★ 何时能合并（何时不能）

#### ★ 4.4.1 一句话判据（本人曾答不出）

★ **自查一句：「我查完之后，要插的是不是同一个东西？」**

```
是   → 能合一：if (!st.insert(x).second) ...
否   → 老老实实两步：先 count / find，再写
```

★ **为什么**：`insert` 只能插入**你传进去的那个值**，它没法替你插入另一个键。

#### ★ 4.4.2 逐题对照

| 题 | 查什么 | 插什么 | 同一键？ | 能合一 |
|---|---|---|---|---|
| 存在重复元素（217）| `x` 在不在 | `x` | ✅ | ✅ `!st.insert(x).second` |
| 两数之和（1）| `target - x` | `x` | ❌ | ❌ 先 `count` 再 `mp[x]=i` |
| 和为 K 的子数组（560）| `cur - k` | `cur` | ❌ | ❌ 先 `ans += mp[cur-k]` 再 `mp[cur]++` |
| 下一个更大元素 I（496）| — | — | 两段循环分开 | 天然不撞 |

★ **牢记：`insert` 帮你把「先查后记」一步做完（它内部就是这么实现的）—— 但仅当查和插是同一个键时。**

### C++ / Python 对照

| 操作 | Python | C++（哈希） | C++（有序） |
|---|---|---|---|
| 创建映射 | `d = {}` | `unordered_map<K,V> mp;` | `map<K,V> mp;` |
| 创建集合 | `s = set()` | `unordered_set<K> st;` | `set<K> st;` |
| 赋值 | `d[k] = v` | `mp[k] = v;` | 同 |
| 取（不存在） | `d[k]` → KeyError | `mp[k]` → **自动创建 0** | 同 |
| 取（带默认） | `d.get(k, 0)` | `mp.count(k) ? mp[k] : 0` | 同 |
| 存在吗 | `k in d` | `mp.count(k)` / `mp.find(k)!=mp.end()` | 同 |
| 删除 | `del d[k]` | `mp.erase(k);` | 同 |
| 遍历 | `for k in d:` | `for (auto& [k,v] : mp)` | 同 |
| 计数 | `Counter` | 手写 `mp[x]++` | 同 |
| 插入集合 | `s.add(x)` | `st.insert(x);` | 同 |
| 集合成员 | `x in s` | `st.count(x);` | 同 |

★ **Python 的 `d[k]` 不存在会 KeyError，C++ 的 `mp[k]` 不存在会「创建 0」—— 两者都不一样，别互相套。** 最接近 Python `d.get(k, 0)` 的写法是 `mp.count(k) ? mp[k] : 0`。

### 4.5 ★ 遍历：`auto&` 与结构化绑定 `[k, v]`

★ **`unordered_map` 遍历时，每个元素是 `pair<const K, V>`。** 最常见写法：

```cpp
for (auto& [k, v] : mp) { ... }
//     ↑①    ↑②③   ↑ 遍历容器
```

| 部分 | 作用 |
|---|---|
| `auto&` | 类型自动推导 + **引用（不拷贝）** |
| `[k, v]` | **结构化绑定**（C++17）：把 pair 拆成键、值 |

**等价展开：**

```cpp
for (auto& p : mp) {
    auto& k = p.first;      // 键
    auto& v = p.second;     // 值
}
```

**三种写法对比：**

| 写法 | 含义 |
|---|---|
| `for (auto p : mp)` | ❌ **拷贝**整个 pair（值大时慢）|
| `for (auto& p : mp)` | ✅ 引用，但要写 `.first/.second` |
| `for (auto& [k, v] : mp)` | ✅✅ 引用 + 命名清晰（推荐）|
| `for (const auto& [k, v] : mp)` | ✅✅ **只读时首选**（省拷贝 + 防误改）|

⚠️ **坑**：值类型是 `vector<string>` 这类大对象时，`auto` 不加 `&` 会**拷贝一整组** → 慢。

★ **`auto&` 的两大用途：① 避免拷贝 ② 能修改原元素**（`for (int& x : v) x = 0;`）。

## 五、★ 核心套路：「边遍历边记录」

★ **绝大多数哈希题都是这个模式的变体：一次遍历，边走边把「已经看过的东西」记进表。**

```
对每个元素 x：
    ① 查：用「过去的数据」解决我和过去的关系     ← 消费者
    ② 记：把 x 贡献给「未来」                     ← 生产者
```

### 5.1 ★ 先查后记（针对「当前 vs 过去」的题）

```cpp
for (int i = 0; i < n; i++) {
    if (mp.count(需要的东西)) { ...用 mp[...]... }   // ① 先查（表里只有 0..i-1）
    mp[当前元素] = i;                                 // ② 后记（此刻我才进入「过去」）
}
```

★ **「查」必须发生在「记」之前，因为：查的语义是「过去有没有」，而你自己只有这一轮结束后，才属于过去。**

### 5.2 ⚠️ 本人真实踩坑：「读到自己」

**现象**：Two Sum 第一版写成「先记后查」，`nums=[3,2,4], target=6` 时返回了 `[0,0]`（自己配自己）。

```cpp
// ❌ 先记后查 → 当前元素进了表，查的时候读到自己
if (!mp.count(target - nums[i])) mp[target - nums[i]] = i;
if (mp.count(nums[i])) { ... }         // 这一步可能命中自己刚插入的
```

**本质**：`mp[键]=值` 一旦执行，当前元素立刻进入「过去」；而「查」本意是问「过去有没有」→ 于是问到了自己。

**正确**：

```cpp
// ✅ 先当消费者（查），再当生产者（记）
if (mp.count(target - nums[i])) return { i, mp[target - nums[i]] };
mp[nums[i]] = i;
```

**判据**：这步「查」会不会恰好碰到刚插入的自己？会 → 调顺序。

★ **口诀：每到一个新元素，先用「过去的数据」解决「我和过去的关系」，再把这个新元素贡献给未来。**

### 5.3 ⚠️ 「先查后记」不是铁律

★ **记住的是它背后的理由（不能读到自己），而不是这个动作本身。**

- 问「当前 vs **过去**」→ 先查后记（Two Sum）
- 问「当前 vs **之后**」→ 顺序不同 / 可能要反向遍历
- 「写表」和「查表」结构上完全分离（如 496 两段循环）→ 天然不撞坑

★ **换题时自问：我这步会不会读到自己？**

### 5.4 ★ 一对多模式：`map<K, vector<V>>`

★ **当一个 key 可能对应「多个」结果时，值必须是容器。**

```cpp
unordered_map<string, vector<string>> mp;   // 值 = vector
mp[key].push_back(x);                        // ✅ 一行归组，不需要 if！
```

★ **`mp[key]` 的「自动创建」在这里是【好事】**：
- key 不存在 → 自动建空 `vector` → 然后 push
- key 已存在 → 直接用已有的那个组

★ **一句话把「存在 / 不存在」两种情况统一了**。

| 之前（1 / 219） | 现在（49） |
|---|---|
| 一个 key → 一个答案 | **一个 key → 一整组** |
| 值 = `int` | 值 = `vector<V>` |

★ **用途：分组 / 分桶类问题**（49 字母异位词分组）。

### 5.5 ★ 「只从起点扩展」技巧（避免重复枚举）

★ **当问题可以看成「链」时，只从「链头」出发，避免同一段被重复数。**

```
链头 = 没有前驱的元素（如 set 里没有 x-1）
```

| 步骤 | 做法 |
|---|---|
| ① 判链头 | `if (st.count(x - 1)) continue;` |
| ② 从链头往后走 | `while (st.count(cur + 1)) ...` |
| ③ 更新答案 | 只对链头触发的链计数 |

★ **复杂度保证：每个元素最多被「非链头跳过」一次、被「扩展」扫一次 → O(n)。**

★ **对比：不剪枝 → 每个元素都往后数 → O(n²)**（128）。

## 六、案例一：两数之和（1）· 哈希表最小入门

题目：找两个数使和为 target，返回**下标**。

### 6.1 暴力 → 哈希

| | 暴力 | 哈希 |
|---|---|---|
| 对每个元素 | 扫后面所有人 | 查表一次 |
| 复杂度 | O(n²) | O(n) |
| 空间 | O(1) | O(n) |

### 6.2 代码（本人独立完成，0ms beat 100%）

```cpp
class Solution {
public:
    vector<int> twoSum(vector<int>& nums, int target) {
        unordered_map<int,int> mp;                  // 值 → 下标
        for (int i = 0; i < (int)nums.size(); i++) {
            int need = target - nums[i];
            if (mp.count(need)) {                   // ① 先查（表里只有 0..i-1）
                return { i, mp[need] };
            }
            mp[nums[i]] = i;                        // ② 后记
        }
        return {};                                  // 题目保证有解
    }
};
```

### 6.3 ⚠️ 本人踩坑

1. **「读到自己」**：第一版「先记后查」→ 见 5.2 节
2. **`mp.count(mp[need])` 套两层**：把「取值」喂进了「查键」
   - ★ `mp.count(键)` = 存在吗；`mp[键]` = 取对应的值。**接收的都是「键」，别把 `mp[...]` 再喂回 `count`。**
   - 这跟 239「存值 vs 存下标」同源 —— 都是**存的东西 / 声明的东西没想清**

## 七、案例二：下一个更大元素 I（496）· 单调栈 + 哈希表

题目：`nums1` 是 `nums2` 的子集，对每个 `nums1[i]` 求它在 `nums2` 里**右边第一个更大的值**（找不到 → -1）。

### 7.1 ★ 关键设计：哈希表键用「值」，不用「下标」

| 方案 | 哈希表内容 | 第二段 |
|---|---|---|
| **本人（值→答案）** | `值 → 下一个更大值` | 直接 `mp.count(nums1[j])` ✅ |
| 另一条（值→位置） | `值 → nums1 下标` | 还得回填 `ans[pos]`，两段耦合 |

★ **用「值」当键，把「两个数组的耦合」消灭了**：第一段只算 nums2 自身答案，第二段只查 nums1，**中间用「值」当桥**。

★ **这就是哈希表的经典用法：用值做索引，解耦两个数组 / 两个步骤。**

### ★ 底层视角：为什么这里用 `unordered_map` 而不是 `map`

- 本题哈希表只用来「拿值查下一个更大值」——**不需要有序**
  ★ **`unordered_map`（哈希表）平均 O(1) vs `map`（红黑树）O(log n)** → 无脑选 unordered
  ⚠️ **但若题目需要「按键有序遍历 / 找前驱后继」→ 必须用 `map`**（496 不需要）。
  ★ 容器选型总表见 `速查手册/C++-内存与调度-速查.md` 第六节。

### 7.2 代码（本人独立完成，18/18）

```cpp
class Solution {
public:
    vector<int> nextGreaterElement(vector<int>& nums1, vector<int>& nums2) {
        int n = nums1.size();
        stack<int> st;
        vector<int> ans;
        unordered_map<int,int> mp;                    // 值 → 下一个更大值
        for (int i = 0; i < (int)nums2.size(); i++) {
            while (!st.empty() && nums2[st.top()] < nums2[i]) {
                int j = st.top();
                st.pop();
                mp[nums2[j]] = nums2[i];              // ★ 弹出时写表（生产者）
            }
            st.push(i);
        }
        for (int j = 0; j < n; j++) {                 // 第二段统一消费（查表）
            if (mp.count(nums1[j])) ans.push_back(mp[nums1[j]]);
            else ans.push_back(-1);
        }
        return ans;
    }
};
```

### 7.3 ★ 496 vs 739 vs 1. Two Sum

| | 每日温度（739） | 下一个更大元素 I（496） | 1. Two Sum |
|---|---|---|---|
| 输入 | 一个数组 | 两个数组 `nums1` `nums2` | 一个数组 |
| 答案 | 距离（`i-j`） | **值**（下一个更大的数） | 下标对 |
| 需要哈希表 | ❌ | ✅（值→答案） | ✅（值→下标） |
| 哈希表键 | — | 值 `nums2[j]` | 值 `nums[i]` |
| 写入时机 | — | 单调栈弹出时 | 每轮末尾 |
| 查表时机 | — | 第二段统一查 | 每轮**开头**（先查后记） |

★ **739 与 496 骨架相同，只改一行：**
```cpp
ans[j] = i - j;                // 739：要距离
mp[nums2[j]] = nums2[i];       // 496：要值（且用哈希表跨数组）
```

★ **⚠️ 本人已两次混淆「返回距离 / 值 / 下标」** —— 读题时先圈出「要什么」。

## 七·补、案例三：存在重复元素 II（219）· 值→最近下标

题目：存在两个下标 `i < j`，使 `nums[i]==nums[j]` 且 `j - i ≤ k`。

### 7.4.1 217 vs 219

| | 217 | 219 |
|---|---|---|
| 判重范围 | 全数组 | 只跟**最近 k 个**比 |
| 哈希表 | `set`（值→存在） | `map`（值→**最近下标**）|
| 关键操作 | `insert().second` | `count` + **覆盖** |

★ **219 = 217 + 「距离约束」** —— 约束让「集合」升级成「映射（存下标）」。

### 7.4.2 代码（本人独立完成，一次过）

```cpp
class Solution {
public:
    bool containsNearbyDuplicate(vector<int>& nums, int k) {
        unordered_map<int, int> mp;               // 值 → 最近下标
        for (int i = 0; i < (int)nums.size(); i++) {
            if (mp.count(nums[i]) && (i - mp[nums[i]]) <= k) return true;   // 先查
            mp[nums[i]] = i;                                                   // 后记（覆盖）
        }
        return false;
    }
};
```

### 7.4.3 ★ 为什么「覆盖」是安全的（生命周期视角）

> **把 `mp[x]` 从旧下标 `j_old` 覆盖成新下标 `j_new`，会不会丢掉本该被判重的配对？**

**不会。** 理由：

- 未来某天来到下标 `i'`，它与旧下标的距离 `i' - j_old` **>** 与新下标的距离 `i' - j_new`
- ★ **新下标离未来更近 → 新下标都满足不了 `≤ k`，旧下标更不可能** → 旧下标对未来无价值 → 覆盖安全

★ **一句话：每个值只留「最近一次」就够，更远的只会更早失效。**（同 239：被踢的下标「更早过期」）

★ **两种淘汰机制**（详见总览「板块关系」节）：
- **过期淘汰**：超出固定边界（239 的窗口）
- **支配淘汰**：有更优替代者（219 覆盖、239 踢尾、496/739 弹出）

### 7.4.4 ⚠️ 本人坑

| # | 坑 | 正确做法 |
|---|---|---|
| 1 | 想「覆盖」用了 `insert` | `insert` **不覆盖**！必须 `mp[k]=v`（见 4.3）|
| 2 | 哈希表存「值→出现过」 | 要算距离 → 必须存**下标** |

## 七·补2、案例四：有效的字母异位词（242）· 数组 vs 哈希的分界

题目：判 `t` 是否为 `s` 的异位词（字符计数完全相同，顺序无关）。

### 7.5.1 代码（本人独立完成，0ms beat 100%）

```cpp
class Solution {
public:
    bool isAnagram(string s, string t) {
        if (s.size() != t.size()) return false;     // 长度不同直接否
        int cnt[26] {};                              // 定长数组（只小写字母）
        for (char c : s) cnt[c - 'a']++;             // s 加
        for (char c : t) cnt[c - 'a']--;             // t 减
        for (int k = 0; k < 26; k++)
            if (cnt[k] != 0) return false;           // 看是否全 0
        return true;
    }
};
```

★ **核心思想：一加一减，抵消回 0。**

### 7.5.2 ★ 为什么用数组不用 `unordered_map`（选型）

| | 数组 `int cnt[26]` | `unordered_map<char,int>` |
|---|---|---|
| 下标范围 | **确定且小**（26） | 任意 |
| 速度 | O(1) 纯数组访存 | 平均 O(1)，但有哈希计算 + 可能 rehash |
| 常数 | 极小 | 大 |
| 何时必须用 | — | 字符集巨大（Unicode）|

★ **分界线一句话：字符集能枚举成小整数 → 用数组；不能（任意 / 巨大）→ 用哈希表。**

★ 验证了本文 §1.1「数组下标的天花板」：242 是「**天花板还没到**」的那一侧。

### 7.5.3 ⚠️ 易混：242 vs 567/438

| | 567 / 438 | 242 |
|---|---|---|
| 结构 | 一个串里找**子串**（窗口在滑）| 两个串**整体**比较 |
| 用滑窗吗 | ✅ | ❌ **不用窗口** |

★ **别一看「异位词」就上滑窗** —— 242 只是「两串计数比较」，没有窗口。

## 七·补3、案例五：字母异位词分组（49）· 一对多

题目：把一堆串按「互为异位词」分组。

### 7.6.1 ★ 关键：值必须是 `vector`（不是下标）

⚠️ **本人第一版卡在这里**：写成 `unordered_map<string,int>`（key→下标）→ 无法存下「一组串」。

★ **判据：同一个 key 可能对应「多个」结果 → 值换成容器。**（见 §5.4 一对多模式）

| 错误（下标版） | 正确（一对多）|
|---|---|
| `unordered_map<string,int>` | `unordered_map<string, vector<string>>` |
| `mp[code] = i`（覆盖，丢数据）| `mp[code].push_back(s)`（追加）|

### 7.6.2 ★ key 编码：数组不能直接当 key

⚠️ **`int cnt[26]` 不能直接当 `unordered_map` 的键**（数组名退化为指针，比较的是地址）→ 必须**编码**。

★ 本人选择：**把计数拼成字符串**（比排序 O(L log L) 更优，O(L)）。

```cpp
string code;
for (int j = 0; j < 26; j++) code += to_string(cnt[j]) + '*';
// 用 '*' 分隔保证不歧义：{1,11} → "1*11*"，{11,1} → "11*1*"
```

★ **key 可以是任意可哈希 / 可比较的类型**（这里是 `string`）。但⚠️ **编码 key 本身有代价**（每串造一个 26 长 string → 大量堆分配），这就是本题 beat 13% 的原因。

### 7.6.3 代码（本人独立完成，一次过）

```cpp
class Solution {
public:
    vector<vector<string>> groupAnagrams(vector<string>& strs) {
        unordered_map<string, vector<string>> mp;   // 计数串 → 该组串
        for (int i = 0; i < (int)strs.size(); i++) {
            int cnt[26] {};
            for (char c : strs[i]) cnt[c - 'a']++;
            string code;
            for (int j = 0; j < 26; j++) code += to_string(cnt[j]) + '*';
            mp[code].push_back(strs[i]);            // ✅ 一行归组，无需 if
        }
        vector<vector<string>> ans;
        for (auto& [k, v] : mp) ans.push_back(v);   // 每 v 是一个 vector<string>
        return ans;
    }
};
```

### 7.6.4 编码方案对比

| 方案 | key | 每组代价 |
|---|---|---|
| 排序 | 排序后的串 | O(L log L) |
| **计数编码（本人）** | 计数拼成的串 | **O(L)** |

### 7.6.5 踩坑

| # | 坑 | 正确做法 |
|---|---|---|
| 1 | 值用 `int` 存下标 | 分组需存一组串 → 值用 `vector<string>` |
| 2 | 归组写成 `if (mp.count(code)) {...}` | 直接 `mp[code].push_back(x)`（自动创建）|
| 3 | key 编码无分隔符 | 加 `*` 分隔，防歧义 |
| 4 | 注释残留旧思路（`index in strs`）| 改掉，防止误导 |

## 七·补4、案例六：最长连续序列（128）· 只从起点扩展

题目：无序数组中，求最长「连续数值序列」的长度（不要求子数组连续，只要值连续）。

例：`[100,4,200,1,3,2]` → `1,2,3,4` 长度 4。
要求 **O(n)**。

### 7.7.1 ★ 核心洞察：链与链头

★ **连续序列 = 一条「链」：`1-2-3-4`。**

⚠️ **本人一开始想用 `map<int, vector<int>>` 存邻居 `x±1`** —— 错在两点：
1. **邻居关系隐含在数值里**（`x+1` 就是 x+1），**不需要预存** → 直接 `set.count(x+1)` 现查
2. 每个数只有 2 个邻居，存 vector 是冗余

★ **正解：用 `unordered_set` 只存「在不在」，靠现查找邻居。**

### 7.7.2 ★ 难点：怎么保证每段只数一次

⚠️ 若对**每个数**都往后数链 → `1-2-3-4` 会被数 4 次 → **O(n²)**。

★ **关键：只对「链头」出发数。**

```
链头 = 没有前驱的数（set 里没有 x-1）
  1-2-3-4 中：1 是链头（没 0）；2/3/4 都不是
```

### 7.7.3 代码（本人独立完成，一次过）

```cpp
class Solution {
public:
    int longestConsecutive(vector<int>& nums) {
        unordered_set<int> st(nums.begin(), nums.end());   // ★ 区间构造：一行去重
        int best = 0;                                       // ★ 空数组返回 0
        for (int x : st) {                                  // 遍历 set（自动去重）
            if (st.count(x - 1)) continue;                  // ① 不是链头 → 跳过
            int len = 1;
            int head = x;
            while (st.count(head + 1)) { len++; head++; }   // ② 从链头往后数
            best = std::max(best, len);
        }
        return best;
    }
};
```

### 7.7.4 ★ 为什么是 O(n)（论证）

★ **每个数最多被 `while` 扫 1 次**（只能作为某链头的后继被扫到）。

以 `1-2-3-4` 为例：
- `1`：不是链头 → 触发 while → 扫过 2,3,4
- `2`：`st.count(2-1)=1` → **跳过**（O(1)）
- `3`、`4`：同样跳过

★ **总工作量 = 建 set O(n) + 每个数 O(1) 判链头 + 每个数最多被 while 扫 1 次 = O(n)。**

⚠️ **如果没有 `if (st.count(x-1)) continue;` 这个剪枝** → 每个数都往后数 → **O(n²)**。它**不是可有可无的检查**。

### 7.7.5 ⚠️ 本人踩坑

| # | 坑 | 正确做法 |
|---|---|---|
| 1 | **`nums[0]` 直接访问** | 空数组时 UB！空数组应返回 0；不要无脑取 `nums[0]` |
| 2 | `best` 初值 1 | 空数组应为 0 → 初值取 `0` |
| 3 | 想用 `map<int,vector<int>>` 存邻居 | 邻居隐含在数值里，用 `set` 现查即可 |
| 4 | 每个数都数链 | 只从链头数（否则 O(n²)）|
| 5 | `int max` 变量名 | 遮蔽 `std::max` → 用 `best` |

### 7.7.6 ★ 底层视角：局部 `int` 的「分配」问题

⚠️ **本人曾担心：`int count` 写在 `if` 里会不会「每轮分配一次」？**

★ **不会。C++ 栈上的 POD（`int`/`double`/指针）不涉及「分配」** —— 只是编译期定好的栈偏移，零开销。

| 类型 | 放循环内 | 有开销吗 |
|---|---|---|
| `int` / `double` / 指针（POD）| 栈偏移复用 | 无 |
| `string` / `vector` / `map` | **每轮构造 + 析构** | ⚠️ 有（可能要分配）|

★ **「复用内存」的直觉只在「有堆分配 / 构造析构的类型」上成立**：此时挪到循环外 + `clear()` 复用（`clear` 保留容量）。
★ 详见 `速查手册/C++-内存与调度-速查.md` 第 3.1 节。

## 十、一句话总结

> ★ **哈希表 = 值当索引的数组，平均 O(1) 查「存在 / 位置 / 次数」。**
>
> **核心套路「边遍历边记录」：每到一个元素，先用「过去」解决和我的关系（查），再把自己贡献给未来（记）。**
>
> **两条铁律：**
> 1. **先查后记**（问「当前 vs 过去」时）—— 否则「读到自己」
> 2. **判断存在用 `count` / `find`** —— `mp[k]` 会偷偷创建
>
> **三条选型律：**
> 3. **字符集小且确定 → 用数组**；否则 → 哈希表（242）
> 4. **一 key 多值 → 值用 `vector`**（`mp[key].push_back`，49）
> 5. **数组不能当 key → 先编码**（49）
>
> ```cpp
> // 哈希表骨架（万能模板）
> unordered_map<K, V> mp;
> for (...) {
>     if (mp.count(需要的东西)) { ... }   // ① 查（消费者）
>     mp[当前元素] = 相关值;               // ② 记（生产者）
> }
> ```
>
> **用途：判重、计数、值→位置、值→答案、跨数组映射、分组编码（1 / 496 / 217 / 219 / 242 / 49 / 128）。**

## 〇、一句话总纲

★ **滑动窗口 = 双指针（控制窗口边界）+ 缓存（维护窗口状态）。**

窗口是数组/字符串上一段**连续**的区间 `[left, right]`，两个指针**只向右移、不回头**，因此每个元素最多进窗口一次、出窗口一次，总复杂度 **O(n)**。

## 一、从暴力到滑窗：为什么会超时

### 1.1 暴力解法的结构

「枚举所有子串」：外层枚举起点 `start`，内层从起点往后延伸终点。

```cpp
for (int start = 0; start < n; start++) {   // n 个起点
    for (int end = start; end < n; end++) { // 每个起点扫到结尾
        // 判断 s[start..end] 是否满足条件（最坏再扫一遍）
    }
}
```

- 子串个数约 `n²/2`，每个判断约 `n` 步 → **O(n³)**
- n = 5×10⁴ 时约 10¹⁴ 次操作 → **必然超时（TLE）**

### 1.2 浪费在哪

相邻两个起点之间**有大量重复劳动**。以 `"abcabcbb"` 为例：

- `start=0` 已检查到 `"abc"` 这段
- `start=1` 又要重新走 `"bc..."`

这段 `"bc"` 被检查了两遍。**滑窗要做的，就是让右指针不回退，消除这种重复。**

> ⚠️ 新手典型错误：想到「用一个 `string` 缓存当前窗口」，但
> 1. 缓存用线性扫描判断重复（O(窗口长)）
> 2. 遇到重复时 `clear()` 把窗口整个清空（边界跳错，丢失中间答案）
> 3. 外层还套 `for start`（等于把滑窗退化成暴力）
>
> 方向是对的（确实要缓存窗口内容），缺的是「双指针 + O(1) 查表」这两个工程细节。

## 二、滑窗的成立条件（能不能用滑窗）

★ 判断一道题能不能用滑窗，问自己三个问题：

### 2.1 是不是「连续子区间」问题？

- 「子串 / 子数组」→ 连续 → 可能是滑窗
- 「子序列」→ 可以不连续 → **不是**滑窗（考虑 DP / 贪心）

### 2.2 窗口状态能不能 O(1) 增量维护？

加一个元素、减一个元素，状态能立刻更新。例：

| 需要的状态 | 能否 O(1) 维护 | 用什么 |
|---|---|---|
| 元素和 | ✅ | 一个 `int sum` |
| 各字符计数 | ✅ | 计数数组 |
| 字符上次出现位置 | ✅ | `last[]` 数组 |
| 窗口内最大值 | ❌（普通变量不行） | 需 **单调队列** `deque` |

### 2.3 有没有单调性？（最关键）

**窗口变大时，条件的变化必须是单调的。**

- LeetCode 3：窗口越长 → 越可能重复 → 缩小窗口只会变好 ✅
- LeetCode 209：窗口越长 → 和越大 → 缩小窗口和只会变小 ✅
- ❌ 反例 560「和恰好为 k 的**个数**」：无单调性 → 不能用滑窗

> ⚠️ 没有单调性硬上滑窗，是最隐蔽的错误来源。

#### ★ 造反例检查法（可操作）

**做法：尝试构造一个「不合法 → 扩一格 → 又合法」的例子。**

如果**能找到**这样的例子 → **无单调性 → 不能用滑窗**。

**实例（560「和恰好为 k 的个数」，k = 1）：**

```text
nums = [1, -1, 1]

窗口 [1]        和 = 1  → 合法 ✅
窗口 [1,-1]     和 = 0  → 不合法 ❌
窗口 [1,-1,1]   和 = 1  → 又合法了！✅
```

★ **“不合法之后又能合法” → 说明「不合法就缩」的策略会漏解 → 没有单调性。**

（本反例正确答案：用**前缀和 + 哈希**，也是 O(n)，但不依赖单调性）

#### ⚠️ 常见思维陷阱：从“工具”出发而非“性质”出发

**错误顺序：**

```text
看到“子数组 + 求和” → 想到滑窗 O(n) → 复杂度好 → 直接用
                                                ↑ 跳过了「适用吗」
```

**正确顺序：**

```text
① 问题有什么性质？（连续？单调？可增量维护？）
② 哪些工具匹配这个性质？
③ 在匹配的工具里选最优的
```

★ **复杂度是「能不能跑完」，正确性是「跑出来对不对」。前提不成立 → 再快也是错答案。**

> 真实教训：某次看到“求和 + 子数组”就直接上滑窗，只考虑了复杂度，忘了检查单调性 —— 而那道题（恰好等于 k 的个数）根本不能用滑窗。

#### 本节总结：三道关

| 前提 | 问自己 | 失败后果 |
|---|---|---|
| **连续性** | 是子串/子数组吗？ | 子序列 → 用 DP/贪心 |
| **可增量维护** | 加一/减一能 O(1) 更新吗？ | 不能 → 升级结构（单调队列/堆） |
| **★ 单调性** | 窗口变大时条件单调变化吗？ | 不单调 → 换前缀和+哈希 / DP |

#### ★ 2.3.1 活反例：和为 k 的子数组 vs 长度最小的子数组

★ **两题描述几乎一样，但一个能滑窗、一个不能 —— 分界线就是「单调性」。**

| | 长度最小的子数组（209）| 和为 K 的子数组（560）|
|---|---|---|
| 数组元素 | **全为正数** | **可能为负** |
| 窗口变大时 | 和**只增不减** → **单调** | 和**无规律** → **不单调** |
| 能用滑窗？ | ✅ | ❌ |
| 正解 | 滑动窗口 | **前缀和 + 哈希** |

**反例演示**（为何 560 不能滑窗）：
```
nums = [1, -1, 1], k = 1
left=0, right=0: 和=1 ✓
扩张到 right=1: 和=0 （变小了！窗口变大但和反而减小）
→ 无法用「和太大就缩左边」的策略
```

★ **本质：正数保证「越长越大」，负数破坏单调性。**

★ **判据：看到「子数组 + 和」先问一句：元素会不会是负数？**
- 全正 → 滑窗
- 有负 → 前缀和 + 哈希（560）
- 有负但要最长/最短 → 前缀和 + 哈希 / DP

★ **本人踩坑**：考试自测时看到「和为 k 的连续子数组个数」直接答「滑窗」—— **忘了检查单调性**。

#### ★ 2.3.2 易混对照：三题都是「子数组 + 和」

| 题 | 元素符号 | 目标 | 板块 |
|---|---|---|---|
| 长度最小的子数组（209）| 全正 | 和 ≥ target 的最短 | **滑窗** |
| 和为 K 的子数组（560）| 可为负 | 和 == k 的个数 | **前缀和 + 哈希** |
| 子数组最大平均数（643）| 可为负 | 定长窗口最大均值 | **滑窗（定长，不需要单调性）** |

## 三、通用模板（背这一个就够）

### 3.1 可变长度窗口

```cpp
int left = 0;
int best = 0;                       // 按题目初始化
for (int right = 0; right < n; right++) {
    // ① 扩张：把 s[right] 纳入窗口，更新状态
    ...

    // ② 收缩：while 窗口不合法，移出 s[left]，left++
    while (/* 窗口不合法 */) {
        ...                         // 移出 s[left] 的副作用
        left++;
    }

    // ③ 结算：此时窗口合法，更新答案
    best = max(best, right - left + 1);
}
return best;
```

**三个动作的填空，就是每道滑窗题的全部差异。**

### 3.2 固定长度窗口

窗口长度固定为 `k`，整体右滑：进一个、出一个。

```cpp
// 先处理前 k 个元素
for (int i = 0; i < k; i++) { 加入 s[i]; }

for (int i = k; i < n; i++) {
    加入 s[i];          // 右端进
    移除 s[i - k];      // 左端出
    更新答案;
}
```

### 3.3 求「最长」vs 求「最短」的区别

| | 求最长 | 求最短 |
|---|---|---|
| 收缩时机 | 窗口**不合法**才收缩 | 窗口**合法就拼命收缩** |
| 更新答案 | 每轮收缩后（窗口合法） | 每次收缩到合法时 |
| 代表题 | 3、1004、424 | 209、76 |

## 四、窗口的「缓存」用什么数据结构

★ 「滑窗」和「缓存」不是二选一：**缓存是滑窗的组成部分**，负责「记住窗口里有什么」。

| 题目类型 | 缓存选什么 | 备注 |
|---|---|---|
| 无重复字符 | `int last[128]` 或 `unordered_set<char>` | 数组更快 |
| 字符计数 | `int cnt[26]` / `cnt[128]` | 字母题常用 |
| 求和 | `int sum` | 最简单 |
| 窗口最值 | `deque`（单调队列） | 结构升级 |
| 键范围大/稀疏 | `unordered_map` | 通用 |

### 4.1 ⚠️ `char` 当数组下标（新手常见疑问）

**C++ 里 `char` 本质是 8 位整数（ASCII 码）**，可以直接当数组下标：

```cpp
char c = 'a';        // 实际存的是 97
last[c];             // 等价于 last[97]
```

- ASCII 范围 0~127 → 开 `int last[128]` 覆盖全部
- 保险起见可开 `int last[256]`
- 用 `unsigned char c` 防止 ASCII > 127 时变负数导致下标越界

### 4.2 这算哈希表吗？

★ **`last[c]` 是「哈希表的思想」，但严格说是哈希表的特例——直接寻址表。**

| | `unordered_map<char,int>` | `int last[128]` |
|---|---|---|
| 映射函数 | 哈希函数（std::hash） | `h(c) = (int)c`（ASCII） |
| 冲突 | 需要处理（链地址/开放寻址） | **零冲突**（每个字符独占一格） |
| 查询 | O(1) 均摊，常数大 | O(1)，常数极小 |
| 内存 | 高 | 低 |

**键的范围小且可枚举（26 个字母 / 128 个 ASCII / n 个编号）时，一律优先用数组代替哈希表。**

## 五、LeetCode 3 完整演进（案例）

题目：找无重复字符的最长子串长度。

### 5.1 暴力 O(n³) —— 超时

每个起点都重新扫到结尾，且用线性扫描判断重复。

### 5.2 朴素滑窗 O(n²)

```cpp
int lengthOfLongestSubstring(string s) {
    int left = 0, best = 0;
    for (int right = 0; right < (int)s.size(); right++) {
        while (containsInWindow(s, left, right - 1, s[right]))
            left++;                       // 一格格试探
        best = max(best, right - left + 1);
    }
    return best;
}
// containsInWindow 内部线性扫描，故仍偏慢
```

### 5.3 最优解 O(n) —— 用 `last[]` 一步跳到位

```cpp
class Solution {
public:
    int lengthOfLongestSubstring(string s) {
        int last[128];
        for (int i = 0; i < 128; i++) last[i] = -1;   // -1 = 未出现

        int left = 0, best = 0;
        for (int right = 0; right < (int)s.size(); right++) {
            unsigned char c = s[right];
            if (last[c] >= left) {        // 旧的 c 还在窗口内 → 重复
                left = last[c] + 1;       // 一步跳到旧 c 的下一位
            }
            last[c] = right;
            best = max(best, right - left + 1);
        }
        return best;
    }
};
```

★ **核心条件 `if (last[c] >= left)` 必须理解**：它问的是「上次出现的位置**还在窗口内**吗」。

⚠️ 不能写成 `if (last[c] != -1) left = last[c] + 1;`。

反例 `"abba"`：处理最后的 `a` 时 `last['a']=0`，但此时 `left=2`，旧的 `a` 早已出窗口，**不该动 left**；若按 `!= -1` 写会把 left 拖回 1，窗口错乱。正确答案是 2。

这也保证了 **left 单调不回头**，从而总复杂度 O(n)。

### 5.4 验证数据

| 输入 | 输出 | 期望 |
|---|---|---|
| `"abcabcbb"` | 3 | 3 |
| `"bbbbb"` | 1 | 1 |
| `"pwwkew"` | 3 | 3 |
| `""` | 0 | 0 |
| `"dvdf"` | 3 | 3（朴素暴力易错得 2） |
| `"abba"` | 2 | 2 |

## 六、LeetCode 209 对比（求最短）

> ★ 本节代码为本人独立完成（一次通过），说明滑窗骨架已能迁移。

```cpp
class Solution {
public:
    int minSubArrayLen(int target, vector<int>& nums) {
        int start = 0;
        int sum = 0;
        int minLenth = INT_MAX;           // 哨兵，表示「还没找到」
        for (int end = 0; end < (int)nums.size(); end++) {
            sum += nums[end];             // ① 扩张
            while (sum >= target) {       // ② 合法就拼命收缩
                minLenth = minLenth < (end - start + 1)
                           ? minLenth : (end - start + 1);   // 结算（合法时）
                sum -= nums[start];       // 先更新答案，再减，顺序不能反
                start++;
            }
        }
        return minLenth == INT_MAX ? 0 : minLenth;   // 无解返回 0
    }
};
```

### 6.1 与 3 题的关键差异（三条）

| 维度 | 3 题（求最长） | 209 题（求最短） |
|---|---|---|
| while 条件 | **不合法**才缩（有重复） | **合法就缩**（sum ≥ target） |
| 更新答案位置 | while 之后（窗口合法） | while **内部**（缩之前那一刻） |
| 无解处理 | 不需要（空串返回 0 天然正确） | 需 `INT_MAX` 哨兵 + 返回 0 |

★ **更新时机为什么必须在 while 内部？**
因为一旦 `sum -= nums[start]`，窗口就可能不再满足条件（变小了但和也变小了）。**最短的合格窗口就是「缩之前」的那一瞬**，所以必须在减之前记录长度。

⚠️ 若把更新写在 while 外面，记录的就是「缩过头之后」的窗口，答案偏小甚至错误；若条件写成 `sum > target`，会漏掉恰好等于 target 的情况。

### 6.2 同样是小瑕疵（不影响过题）

```cpp
for (end; end < nums.size(); end++)   // ① 初始化语句 end 没用
                                       // ② int 与 size_t 比较有符号警告
```

建议：`for (int end = 0; end < (int)nums.size(); end++)`。

## 七、LeetCode 643 案例（固定长度窗口）

题目：长度固定为 k 的子数组，求最大平均值。

> ★ 本节代码为本人独立完成（一次通过，但踩过一个类型坑，见 7.2）。

### 7.1 固定窗口骨架

与可变长窗口的**根本区别**：长度固定，**不用 while 收缩**，而是「进一个、出一个」。

```cpp
class Solution {
public:
    double findMaxAverage(vector<int>& nums, int k) {
        // ① 先建初始窗口：前 k 个
        double average = 0;
        for (int i = 0; i < k; i++) average += 1.0 * nums[i] / k;

        // ② 整体右滑：进一个、出一个
        double maxAverage = average;
        int start = 0;
        for (int end = k; end < (int)nums.size(); end++) {
            average += 1.0 * nums[end] / k;    // 右端进
            average -= 1.0 * nums[start] / k;  // 左端出
            start++;
            maxAverage = maxAverage >= average ? maxAverage : average;
        }
        return maxAverage;
    }
};
```

| | 可变长窗口（3、209） | 固定长窗口（643） |
|---|---|---|
| 窗口长度 | 变 | 固定 k |
| 收缩方式 | `while` 根据条件收缩 | **无 while**，直接「进一出一」 |
| 循环起点 | `right = 0` | `end = k`（先建好前 k 个） |
| 状态更新 | 扩张/收缩分开 | 每步只做「加右减左」 |

### 7.2 ⚠️ 踩坑：把平均值变量写成了 `int`

```cpp
int average = 0;                    // ✗ 错
average += 1.0 * nums[i] / k;       // 1.0*... 是 double，存入 int 时被截断
```

- `1.0 * 12 / 5 = 2.4` → 存进 `int` 变成 `2`，**每次累加都丢精度**
- 症状：**算法逻辑全对、样例差不多，但答案不对**，排查半天
- 编译器不报错（`double → int` 只是隐式转换，顶多 warning）

★ **排查教训：错的不是算法，是类型。** 遇到「逻辑全对但答案不对」时，先怀疑**变量类型 / 整数除法截断**。

### 7.3 更稳的写法：先求和，最后只除一次

```cpp
double sum = 0;
for (int i = 0; i < k; i++) sum += nums[i];
double best = sum;
for (int end = k; end < (int)nums.size(); end++) {
    sum += nums[end] - nums[end - k];   // 整数加减，无误差
    best = best > sum ? best : sum;
}
return best / k;                        // 全程只除这一次
```

★ **浮点数能不碰就不碰**：中间过程用整数（和），只在最后除一次，避免误差累积。

## 八、LeetCode 567 案例（固定长度 + 计数）

题目：s2 中是否存在 s1 的某个排列作为子串。

> ★ 本题本人独立完成，踩了两个坑（下标越界、`char` 计数溢出），均已修复并 AC。

### 8.1 「是 s1 的排列」怎么理解

★ **「排列」在这里只约束「内容」，不约束「顺序」：**

- 「**子串**」这个词 → 锁定「连续 + 定长」，位置不能乱
- 「**排列**」这个词 → 只要求字符构成相同，顺序随意

所以题目等价于：

> **在 s2 上滑一个长度固定为 `s1.size()` 的窗口，看哪个窗口的字符计数与 s1 完全相同。**

| | 643（固定长） | 567（固定长 + 计数） |
|---|---|---|
| 窗口长度 | 给定 k | `s1.size()` |
| 窗口状态 | 一个 `sum` | 计数数组 |
| 判断条件 | 比大小取最大 | **计数数组是否相等** |

### 8.2 坑一：上界来自 A、索引 B → 堆越界

```cpp
int k = s1.size();          // 上界来自 s1
for (int i = 0; i < k; i++)
    c_s2[s2[i]]++;          // 索引的是 s2 ← 没确认 k ≤ s2.size()
```

若 `s1` 比 `s2` 长，则 `s2[i]` 越界，AddressSanitizer 报 `heap-buffer-overflow`。

★ **通用模式：「循环上界来自 A，但访问的是 B」时，必须先确认上界在 B 上合法。**

```cpp
if (s1.size() > s2.size()) return false;   // 长度不够，前提不成立
```

### 8.3 坑二：计数数组用 `char` 会溢出

```cpp
char c_s1[128] {};          // ✗ s1 长度可达 10^4，同一字符可能超 127 次
c_s1[s1[i]]++;              // char 溢出 → 变负数 → 比较出错
```

★ **计数数组一律用 `int`**，反正只多几百字节。

### 8.4 骨架小结

```text
1. if (s1.size() > s2.size()) return false;   // 前提检查
2. 统计 s1 的字符计数 c_s1                     // int 数组
3. 统计 s2 前 k 个字符 → c_s2
4. 窗口滑动：每步「进右字符、出左字符」
5. 每步比较 c_s1 与 c_s2，相等则 true
6. 遍历完未找到 → false
```

可选优化：每步都比 128 个计数是 O(128n)。可维护一个「已匹配字符种类数」计数器，将判断降为 O(1)（76 题会用到）。

### 8.5 关于检查时机（一个容易绕晕的点）

固定窗口共 **n - k + 1** 个（n = s2 长度，k = s1 长度），**每一种写法都必须把这 n-k+1 个窗口检查一遍**。

区别只在于「哪个端点留给循环外检查」：

| 循环内写法 | 循环内检查的窗口 | 循环外补检查 |
|---|---|---|
| 先检查、后滑动 | `[0,k-1]` … `[n-k-1, n-2]` | **最后一个** `[n-k, n-1]` |
| 先滑动、后检查 | `[1,k]` … `[n-k, n-1]` | **第一个** `[0, k-1]` |

★ **两种都正确、工作量相同，没有优劣。** 关键认知是：

> 不是「哪种顺序会漏」，而是「只要循环覆盖不全所有窗口，就要在循环外补一次检查」。
>
> 判断标准：哪个端点放在循环外更符合直觉就选哪个。

⚠️ 常见误解：「先滑动后检查就不会漏了」——错。若把检查挪到循环末尾而不处理初始窗口，一样会漏。

## 九、LeetCode 1004 案例（可变长求最长 · 判据替换）

题目：最多翻 k 个 0 后，最长连续 1 的长度。

### 9.1 题意转换

★ **「最多翻 k 个 0」 ⟺ 「区间内 0 的个数 ≤ k」**

因为要把一段区间变全 1，必须翻转区间内**所有** 0。于是问题变为：

> **找最长子数组，使其中 0 的个数 ≤ k。**

### 9.2 代码（本人独立完成，AC 0ms / beat 100%）

```cpp
class Solution {
public:
    int longestOnes(vector<int>& nums, int k) {
        int start = 0, zeroCount = 0, best = 0;
        for (int end = 0; end < (int)nums.size(); end++) {
            if (nums[end] == 0) zeroCount++;     // ① 扩张
            while (zeroCount > k) {              // ② 不合法就缩
                if (nums[start] == 0) zeroCount--;
                start++;
            }
            best = (end - start + 1) > best ? (end - start + 1) : best;  // ③ 结算
        }
        return best;
    }
};
```

### 9.3 与 3 题的对比（骨架完全一致，只换了判据）

| | 3 题 | 1004 |
|---|---|---|
| 窗口状态 | `last[]` 字符上次位置 | `zeroCount` 窗口内 0 的个数 |
| 不合法判据 | 窗口内有重复字符 | `zeroCount > k` |
| 收缩副作用 | 调 `left` | `if (nums[start]==0) zeroCount--` |
| 模式 | 可变长求最长 | **同左** |

★ **判据换了，骨架没动 —— 这就是滑窗的核心价值。**

### 9.4 ⚠️ 走过的弯路：用「全局计数」去索引窗口

第一版想法：记住每个 0 的下标，超 k 时直接跳到那个 0 后面。

```cpp
vector<int> zeroIndex;                    // 存所有 0 的下标（全局）
if (nums[end] == 0) { zeroIndex.push_back(end); count++; }
start = zeroIndex[count - 1 - k];         // ❌
```

**两个错：**

1. **`count` 是全局累计的 0 数，不是窗口内的 0 数** → 两者会越差越多
2. **差一**：丢下标 i 的元素，新起点是 `i + 1`，不是 `i`

★ **根本原因：滑窗只应该维护「窗口内」的状态。被移出窗口的 0，在全局计数和全局数组里还留着，导致坐标系错乱。**

**若要真「跳到 0」**，需要让 `zeroIndex` 只含窗口内的 0（即当成**队列**：进右端、出左端）—— 那已经是 `deque` 的雏形了（239 题的伏笔）。

### 9.5 教训小结

★ **「聪明」的跳过写容易算错下标；先用标准 `while` 形态把题过了，想优化再换。**

★ **标准 `while` 版本质就是「跳到 0」**：它一格一格走，但那几格必然都是 1（遇到第 1 个 0 就停了）。

## 十、LeetCode 76 案例（最小覆盖子串 · Hard）

题目：返回 s 中涵盖 t 所有字符（含重复）的最短子串，不存在返回 `""`。

> ★ 本题本人独立完成，一次通过（268/268），103ms / beat 9.23%。

### 10.1 与前面题目的三个关键差异

| | 567 / 438 | 76 |
|---|---|---|
| 窗口长度 | 固定 = t.size() | **可变** |
| 判据 | 计数**相等** | 计数 **≥** t（窗口可含多余字符） |
| 模式 | 固定长 | 可变长 **求最短** |
| 返回 | bool / 位置 | **子串本身** |

★ **判据是「≥」不是「==」** —— 这是 76 与 567 最本质的区别。

### 10.2 代码（本人独立完成）

```cpp
class Solution {
public:
    string minWindow(string s, string t) {
        int l_s = (int)s.size(), l_t = (int)t.size();
        if (l_t > l_s) return "";                   // 前提检查（防越界 + 样例3）

        int s_char_count[128] {};
        int t_char_count[128] {};
        for (int i = 0; i < l_t; i++) t_char_count[t[i]]++;

        int start = 0, min_l_window = INT_MAX;
        int f_start = 0;
        for (int end = 0; end < l_s; end++) {
            s_char_count[s[end]]++;                  // ① 扩张
            while (isMathed(s_char_count, t_char_count)) {   // ② 覆盖就缩
                int l_window = end - start + 1;
                if (l_window < min_l_window) {        // ③ 记录（缩之前）
                    min_l_window = l_window;
                    f_start = start;
                }
                s_char_count[s[start]]--;            //     移出左端
                start++;
            }
        }
        if (min_l_window == INT_MAX) return "";
        return s.substr(f_start, min_l_window);       // 用 起点+长度
    }

    bool isMathed(int* s, int* t) {
        for (int i = 0; i < 128; i++)
            if (s[i] < t[i]) return false;            // ★ 即「≥」判据
        return true;
    }
};
```

### 10.3 三个写法亮点

1. **`if (s[i] < t[i]) return false;`** —— 直接表达「窗口里这个字符不够」，等价于「计数 ≥」判据，比反过来写更清楚
2. **记录 `f_start` + `min_l_window`（长度）** —— 正好匹配 `substr(pos, len)`，比记 `f_end` 更自然
3. **`while (isMathed(...))`** —— “覆盖就缩”，符合「求最短」的节奏（与 1004 的“不合法才缩”正好相反）

### 10.4 性能现状与优化方向（未做）

```cpp
bool isMathed(int* s, int* t) {
    for (int i = 0; i < 128; i++) ...   // 每步 O(128)
}
```

- 总复杂度 **O(128·m) = O(m)**，常数 128 → 103ms（beat 9.23%）
- ★ **优化方向：维护 `matched`（已满足的字符种类数），将判断降为 O(1)**
  - 扩张时：加**之前** `s[c] < t[c]` → 加完可能达标 → 判断并 `matched++`
  - 收缩时：减**之前** `s[c] == t[c]` → 减完就不够 → `matched--`（要区分“刚好够”和“超出”）
  - 目标：`matched == t 中不同字符种数`
- **本次未做**，按「过不了再优化」策略留待以后（与 239 一起学）

### ★ 底层视角：`substr` / 字符串拼接的拷贝开销

- `s.substr(pos, len)` **会生成一个新的 string**（拷贝 len 个字符）—— 本题只调一次，无所谓；若在循环里调就是 O(n²)
- ⚠️ **`s = s + c` vs `s += c`**：前者生成新串 + 拷整个 s + 赋值 → **每次 O(n)**；后者原地追加 → 均摊 O(1)
  ★ **循环拼字符串永远用 `+=`**。
- ⚠️ **传参拷贝**：`void f(string s)` 会把整个串拷一遍（O(n)） → **用 `const string&`**
  ★ 详见 `速查手册/C++-内存与调度-速查.md` 第四节。

## 十二、边界防御（避坑 11 / 13 / 14 / 15 的系统总结）

★ **核心认知：防御性检查 ≠ 返回值逻辑。两者是两个抽屉，换题时只有前者永远要搬。**

### 12.1 两个抽屉

```text
抽屉 A：数组安全（永远要）
  - 用 k 索引另一个容器前，确认 k ≤ 它的长度
  - 存在理由与「题目要什么返回值」无关

抽屉 B：返回值逻辑（看题目）
  - 找不到返回什么（本题 vector 找不到自然是空 vector）
  - 无解返回什么
```

### 12.2 真实案例：567 → 438 漏搬前提检查

```cpp
// 567（写对了）
bool checkInclusion(string s1, string s2) {
    if (s1.size() > s2.size()) return false;   // ✅ 有
    ...
}

// 438（漏了）
vector<int> findAnagrams(string s, string p) {
    // ❌ 缺 if (p.size() > s.size()) return {};
    for (int i = 0; i < (int)p.size(); i++)
        char_s[s[i]]++;        // p 比 s 长时 → s[i] 越界（UB）
    ...
}
```

**为什么漏了？** 因为把检查理解成了「返回值逻辑」：

| 错误推理 | 正确认知 |
|---|---|
| 返回 bool，题目说找不到返回 false → 所以要处理边界（567） | 检查的**目的**是防越界，不是定义返回值 |
| 返回 vector，题目没说找不到怎么办 → 不用处理（438） | **无论题目写不写，都要写**（否则数组越界） |

★ **换题时，抽屉 A 的内容永远跟着搬；抽屉 B 才看题目调整。**

### 12.3 「上界来自 A、索引 B」的通用模式

```cpp
int k = s1.size();          // 上界来自 s1
for (int i = 0; i < k; i++)
    arr[s2[i]]++;           // 索引的是 s2 ← 没确认 k ≤ s2.size()
```

★ **只要出现「用 A 的长度去索引 B」的结构，就要先验证 `A.size() ≤ B.size()`。**

### 12.4 魔数边界：手滑写错循环上界

```cpp
int c[128] {};
for (int i = 0; i < 127; i++)   // ❌ 少比了下标 127
    if (a[i] != b[i]) return false;
```

- 数组是 `[128]`，合法下标 `0~127`，写 `< 127` 就漏了最后一个
- 本题数据只含小写字母，127 位恒为 0 == 0，**恰好没错**（掩过去的 bug）

**正确做法：**

| 方案 | 写法 |
|---|---|
| 用常量 | `const int ALPHA = 128; for (int i = 0; i < ALPHA; i++)` |
| 用 `std::equal` | `return std::equal(a, a + 128, b);` |
| ★ 开 26（题目限小写字母） | `int c[26]{}; c[s[i] - 'a']++;` 更贴切且不易错 |

### 12.5 差一错误：丢掉元素 / 区间长度 / 起点边界

★ **高频错误家族，仅此于越界。口诀：「起点是元素后面，长度要 +1」。**

#### 真实案例（1004 的「跳到 0」想法）

想用「记住 0 的位置」直接跳 `start`：

```cpp
start = zeroIndex[count - 1 - k];        // ❌ 两处错
start = zeroIndex[count - k] + 1;        // ✅
```

画出来：

```text
数组:  ... 1 1 0 1 1 ...
              ↑   ↑
          被丢的  start
            0    (= 0的位置 + 1)
```

**丢掉下标 3 的 0 后，窗口从下标 4 开始 → `start = 3 + 1 = 4`。**

#### 常见的差一陷阱

| 场景 | 易错 | 正确 |
|---|---|---|
| 丢掉下标 i 的元素 | `start = i` | `start = i + 1` |
| 区间 `[l, r]` 的长度 | `r - l` | `r - l + 1` |
| 从 i 开始往后 k 个 | 到 `i + k` | 到 `i + k - 1` |
| 固定窗口初始长度 | `end - start` | `end - start + 1` |
| 循环上界 | `i < n` 与 `i <= n` 混溆 | 看下界是否含 n |

★ **核心：想清楚下标的「含 / 不含」** —— 区间是 `[left, right]` 闭区间（含右端）还是 `[left, right)` 半开？两种混用就是差一的来源。

★ **本笔记统一约定：窗口是 `[start, end]` 闭区间，长度 = `end - start + 1`。**

### 12.6 边界防御自检清单（写完扫一眼）

```text
1. 循环上界来自 A、索引 B 时，验证过 A.size() ≤ B.size() 吗？
2. 数组大小与循环上界一致吗？（128 数组就写 < 128）
3. 空输入 / 长度不足的极端情况，循环会越界吗？
4. 题目约束允许的最短输入，我的代码会怎样？
```

★ **这四条不需要「学」，只需要「检查」，代价几乎为零，但能挡掉目前踩过的所有 UB。**

## 十三、类型速查表（避坑 9~10 的系统总结）

★ **所有类型坑的共同根因：选的类型「装不下」你要装的值，或「精度不够」。**

### 13.1 各类型能装多少

| 类型 | 大小 | 范围 | 能装什么 |
|---|---|---|---|
| `char` | 1 字节 | -128 ~ 127（signed，GCC 默认） | 字符、小整数、**0/1 标记** |
| `unsigned char` | 1 字节 | 0 ~ 255 | 字符、小计数 |
| `short` | 2 字节 | ≈ -3.2万 ~ 3.2万 | 中等整数 |
| `int` | 4 字节 | ≈ -21亿 ~ 21亿 | **计数、累加、大部分整数** |
| `long long` | 8 字节 | ≈ ±9×10¹⁸ | **乘积、大和、防溢出** |
| `float` | 4 字节 | 约 7 位有效数字 | 精度要求低的小数 |
| `double` | 8 字节 | 约 15 位有效数字 | **平均值、除法结果、坐标** |

⚠️ `char` 到底是有符号还是无符号是「**实现定义**」的（不同编译器可能不同），GCC/Clang 默认 signed。**不要依赖它，存计数就别用 `char`。**

### 13.2 「什么类型装什么」速查

| 你要装的值 | 用什么 | 反例 |
|---|---|---|
| 字符 / 小标记（0/1） | `char` / `bool` | — |
| **计数、累加（可能上千上万）** | `int` | ⚠️ `char` 会溢出（567） |
| **平均值、除法结果** | `double` | ⚠️ `int` 会截断（643） |
| 两数相乘 / 大范围求和 | `long long` | ⚠️ `int` 会溢出 |
| 数组下标计算 | `size_t`（`vector::size()` 返回值） | ⚠️ 与 `int` 混用有符号警告 |

### 13.3 整数除法的陷阱

```cpp
int a = 7, b = 2;
a / b;              // = 3（整除，小数被丢弃）
1.0 * a / b;        // = 3.5（先提升为 double）
(double)a / b;      // = 3.5（显式转换）
```

★ **两个整数相除 = 整除**，小数直接被丢掉。要小数结果，必须至少一边先变 `double`。

### 13.4 溢出是「静默」的（最难查）

```cpp
char c = 127;
c++;                // c 变成 -128，不报错、不崩溃
```

```cpp
int x = 2000000000;
x = x + x;          // 溢出，结果未定义（UB），不报错
```

★ **溢出/截断/整除丢小数的共同特点：编译不报错、运行不崩溃，只是悄悄给出错误结果。**
这也是它们比崩溃更难查的原因 —— **只能靠「变量类型对不对」来预防，不能等错误发生再排。**

### 13.5 自问口诀

> **「我要装的值，最大/最精确到什么程度？选的类型装得下、够精确吗？」**
>
> - 装小数 → `double`
> - 装计数/累加（可能上万）→ `int`
> - 装乘积/大和 → `long long`
> - 只装 0/1 标记 → `char` / `bool` 也行

### 13.6 `size_t` 与符号陷阱

**`size_t` 是什么：** 标准库用来表示「大小 / 长度 / 下标」的**无符号整数**（64 位系统上 8 字节，相当于 `unsigned long`）。

几乎所有「长度」接口都返回它：

```cpp
s.size();      // size_t
v.size();      // size_t
sizeof(int);   // size_t
```

#### 为什么它是高频坑

★ **C++ 规则：有符号与无符号比较时，有符号的会被转成无符号。**

```cpp
int i = -1;
s.size() = 5;
// 实际比较：(unsigned)(-1) < 5
// 即 18446744073709551615 < 5  →  false（不是 true！）
```

这就是编译器警告的来历：

```text
warning: comparison of integer expressions of different signedness:
         'int' and 'std::__cxx11::basic_string<char>::size_type'
```

#### 两个经典雷

```cpp
// 雷 1：空容器
string s = "";
s.size() - 1;      // 不是 -1，是 18446744073709551615！

// 雷 2：无符号倒序
for (size_t i = n - 1; i >= 0; i--) { ... }
// i 减到 0 后再 -- 变成巨大数，i >= 0 永远真 → 死循环
```

#### 三种处理方式

| 方式 | 写法 | 适用 |
|---|---|---|
| 全用 `size_t` | `for (size_t i = 0; i < s.size(); i++)` | 无警告，但**不能 `i--` / 相减** |
| 强转 `int` | `for (int i = 0; i < (int)s.size(); i++)` | ★ 算法题推荐 |
| 范围 for | `for (char c : s)` | 不需要下标时最安全 |

#### ★ 算法题推荐规则

```cpp
// 1. 需要下标遍历：统一用 int + 强转
for (int i = 0; i < (int)s.size(); i++)

// 2. 不需要下标：用范围 for
for (char c : s)

// 3. 避免 size() - 1 和无符号倒序（前者用 int，后者写 int i = (int)n - 1）
```

理由：算法题的长度不会超过 `INT_MAX`，用 `int` 不仅安全，还避免了所有无符号的坑。

#### 危险场景速查

| 场景 | 危险 | 原因 |
|---|---|---|
| `int i` 与 `size()` 比较 | ⚠️ | 有符号↔无符号转换 |
| `size() - 1` 当 `size() == 0` | ⚠️⚠️ | `0 - 1` 在无符号下是巨大数 |
| 倒序 `for (size_t i = n-1; i >= 0; i--)` | ⚠️⚠️ | `i >= 0` 对无符号永远为真 → 死循环 |
| 下标相减 `a - b`（b > a） | ⚠️⚠️ | 得到巨大正数而非负数 |

## 十六、相关但「不是滑窗」的易混点

| 场景 | 该用什么 | 为什么不是滑窗 |
|---|---|---|
| 求**子序列**（可不连续） | DP / 贪心 | 不要求连续 |
| 子数组和**恰好等于 k 的个数** | 前缀和 + 哈希 | 无单调性 |
| 窗口内**最大值/最小值** | 滑窗 + 单调队列 | 状态需结构升级（仍算滑窗家族） |
| 只查询某元素**是否存在** | 哈希集合 | 根本不需要窗口 |
| 两数之和（有序数组） | **对撞双指针** | 从两端往中间，方向相反 |

> 「对撞双指针」和「滑动窗口」都叫双指针，但移动方向相反（一个相向，一个同向），别混淆。

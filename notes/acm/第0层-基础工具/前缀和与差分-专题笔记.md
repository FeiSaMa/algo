## 〇、一句话总纲

★ **前缀和解决「多次区间求和」，差分解决「多次区间加值」—— 两者互为逆运算。**

```
前缀和：预计算累加和 → 任意区间和 O(1)
差分  ：只记两个端点的变化 → 多次区间加 O(1)，最后前缀和还原
```

★ **共同思想：把「重复的计算」预先合并 / 推迟结算，避免每次重算。**

## 一、为什么需要它（问题的来源）

### 1.1 场景：多次区间操作

**场景 A（前缀和）**：数组不动，但**反复问某段的和**

```
nums = [1, 2, 3, 4, 5]
问 nums[1..3] 的和？  nums[0..4] 的和？  nums[2..4] 的和？……
```

- **暴力**：每次都重新累加 → 单次 O(区间长度) → 问 m 次 = O(m·n)
- ⚠️ **重复计算了大量相同的前缀** → 浪费

**场景 B（差分）**：反复对某段**整体加值**

```
把 nums[1..3] 每个都 +5；
再把 nums[0..2] 每个都 +3；……
```

- **暴力**：每次都逐个元素加 → 单次 O(区间长度) → O(m·n)

★ **两个场景的共同点：区间操作被反复做 → 需要把「区间级操作」降到 O(1)。**

## 二、前缀和

### 2.1 ★ 定义（半开区间！）

```cpp
pre[i] = nums[0] + nums[1] + ... + nums[i-1]      // 前 i 个元素之和
```

★ **`pre[i]` 是「前 i 个元素」的和（半开 `[0, i)`）** —— 和 C++ 的 `begin/end`、`substr` 一个风格。

```
nums:  [1,  2,  3,  4,  5]
pre:   [0,  1,  3,  6, 10, 15]
        ↑ pre[0]=0（空区间）
```

| pre 下标 | 含义 |
|---|---|
| `pre[0]` | 空区间，和 = 0 |
| `pre[i]` | `nums[0..i-1]`（前 i 个）|
| `pre[n]` | 全数组和 |

### 2.2 ★ 区间和公式

```
sum(nums[l..r]) = pre[r + 1] - pre[l]
```

★ **记忆：`[l, r]` 的和 = 「r 的后一格」减「l」**。

```
nums[1..3] = 2+3+4 = 9
= pre[4] - pre[1] = 10 - 1 = 9 ✓
     ↑ r=3 → r+1=4    ↑ l=1
```

### 2.3 ★ 构造（O(n)）

```cpp
vector<long long> pre(n + 1, 0);          // ★ n+1 个，pre[0]=0
for (int i = 0; i < n; i++) {
    pre[i + 1] = pre[i] + nums[i];
}
```

★ **`pre[0] = 0` 是必须的**：让「从下标 0 开始的区间」也能用统一公式（`l=0 → pre[0]`），不用特判。

### 2.4 ★ 为什么用 `long long`

★ `pre[n]` 可能 = n × 单值。n=10⁵、值=10⁹ → 10¹⁴，**远超 int（~2.1×10⁹）→ 溢出**。

★ **规则：前缀和 / 差分数组、以及累加变量一律 `long long`。**

## 三、差分

### 3.1 ★ 定义

```cpp
d[i] = nums[i] - nums[i-1]        // 相邻之差；d[0] = nums[0]（nums[-1] 视作 0）
```

```
nums:  [3,  1,  4,  1,  5]
d:     [3, -2,  3, -3,  4]
```

★ **差分 = 记录「变化量」。**

### 3.2 ★ 逆运算关系（核心）

| 方向 | 操作 |
|---|---|
| `nums` → `d` | 相邻相减（**差分**）|
| `d` → `nums` | 累加（**前缀和**）|

```
d:      [3, -2,  3, -3,  4]
前缀和:  [3,  1,  4,  1,  5]  = nums ✓
```

### 3.3 ★ 区间 +v 只改两个点

对区间 `[l, r]` 全体 `+v`：

```cpp
d[l]     += v;
d[r + 1] -= v;       // ← 只改这两格，其他不动
```

★ **为什么成立**：区间内部相邻差不变（都 +v，抵消），**只有 `l` 起点和 `r+1` 终点后的差变了**。
- `d[l]` 处的 `+v` 通过前缀和**一路传到 `r`**
- 到 `d[r+1]` 被 `-v` **抵消** → 效果就是「只有 `[l,r]` 被 +v」

**验证**：`nums=[0,0,0,0,0]`，`[1,3] += 5`

```
d 原本:    [0, 0, 0, 0, 0]
d[1] += 5: [0, 5, 0, 0, 0]
d[4] -= 5: [0, 5, 0, 0,-5]      ← r+1 = 4
前缀和还原: [0, 5, 5, 5, 0]  ✓
```

### 3.4 ★ 完整流程

```cpp
int n = nums.size();
vector<long long> d(n + 1, 0);              // ★ n+1

// ① 构造差分（若 nums 初始非 0）
for (int i = 0; i < n; i++) {
    d[i]     += nums[i];
    d[i + 1] -= nums[i];                    // 等价于 d[i] = nums[i] - nums[i-1]
}

// ② 多次区间加
// d[l] += v;  d[r + 1] -= v;

// ③ 前缀和还原
long long cur = 0;
for (int i = 0; i < n; i++) {               // ★ 只到 n-1
    cur += d[i];
    ans[i] = cur;
}
```

### 3.5 ★ 边界：`d` 开 `n+1`（重点）

★ **`d` 恒开 `n+1`**：前 `n` 格是真正的差分，**第 `n+1` 格（下标 `n`）只为「`r = n-1` 时 `d[r+1]` 不越界」而存在，不影响结果**。

| 场景 | 处理 |
|---|---|
| `l = 0`（从开头）| **无需特判**（`d[0]` 天然对应起点）|
| `r = n-1`（到结尾）| `d[n] -= v` 落在多开的一格，**靠 `n+1` 兜底** |
| 还原循环上界 | **`i < n`**（`d[n]` 不参与）|

⚠️ **三个易错点**：

| # | 坑 | 后果 |
|---|---|---|
| 1 | `d` 只开 `n` | `d[r+1]` 越界 **UB / MLE** |
| 2 | 还原写成 `i <= n` | 多算一格 |
| 3 | 用 `int` 存 `d` / `cur` | 溢出 |

★ **坑 1 和坑 2 是一对**：一个「多开一格」，一个「少算一格」，配合才对。

### 3.6 ⚠️ 1-based 编号 → 0-based 下标（本人真实踩坑）

★ **当题目编号从 1 开始**（如 1109 航班 1..n）时：

| 题目（1-based） | 差分数组（0-based） |
|---|---|
| 区间 `[first, last]` | 0-based 区间 `[first-1, last-1]` |
| **`d[first - 1] += v`** | 起点（**减 1**）|
| **`d[last] -= v`** | 终点的后一格（**不减**，因为 `(last-1)+1 = last`）|

★ **记忆法：起点减 1，终点不减。**

⚠️ **本人踩坑（1109）**：漏了 `-1` → 整体右移一格 → `d[end+1]` 在第一格就写 `d[1]`，末尾 `d[n+1]` **越界写 → MLE**。

## 四、★ 组合：前缀和 + 哈希（560）

题目：求**和为 k 的连续子数组的个数**。

### 4.1 关键转化

```
nums[i..j] 的和 = pre[j+1] - pre[i] = k
→ 移项：pre[i] = pre[j+1] - k
```

★ **换个角度：遍历到 `j` 时，我需要知道「之前有多少个 `pre[i]` 等于 `pre[j+1] - k`」。**

→ **「计数」问题 → 哈希表**（`unordered_map<前缀和值, 出现次数>`）。

### 4.2 ★ 与 Two Sum 同源

| | 1. Two Sum | 560 |
|---|---|---|
| 问什么 | 之前有没有 `target - x` | 之前有**多少个** `cur - k` |
| 哈希存什么 | 值 → 下标 | 前缀和 → 出现次数 |
| 查的时机 | **先查后记** | **先查后记** |

★ **区别只在于 560 是「计数」而非「找一个」** → `ans += mp[key]`。
★ **「先查后记」纪律在这里同样适用**（否则「读到自己」）。

### 4.3 代码（本人独立完成，一次过）

```cpp
class Solution {
public:
    int subarraySum(vector<int>& nums, int k) {
        unordered_map<long long, int> mp;
        mp[0] = 1;                              // ★ 前缀和 0 出现 1 次（空区间）
        long long cur = 0;
        int ans = 0;
        for (int x : nums) {
            cur += x;                           // 当前前缀和
            ans += mp[cur - k];                 // ① 先查（mp[] 不存在自动 0，不用 count）
            mp[cur]++;                          // ② 后记
        }
        return ans;
    }
};
```

### 4.4 ⚠️ 两个坑（本人真实踩坑）

| # | 坑 | 教训 |
|---|---|---|
| 1 | `mp[0] = 0`（应为 1）| 「空区间」`pre[0]=0` 必须计数为 **1**，否则漏掉「从下标 0 开始」的答案 |
| 2 | **预存 `pre` 数组 + 哈希计数混用 → `pre[0]` 重复计数** | 干脆**不预存数组**，用 `cur` 增量累加 |

#### ★ 4.4.1 为什么 `mp[0] = 1`（完整推导·本人曾答不出）

★ **`mp` 存的是「某个前缀和值出现过几次」：**
```
mp[前缀和的值] = 出现次数
```

★ **`pre[0] = 0` 是「空区间」的前缀和，它必然存在 1 次。**

```
nums = [3], k = 3
pre = [0, 3]
     ↑ 空区间，和 = 0 → mp[0] 应该是 1
```

★ **漏了会怎样**：
```
遍历到 pre[1] = 3 时，要找「之前有多少个 pre[i] == 3 - 3 = 0」
→ 答案就是 mp[0]
→ 若 mp[0] = 0（或没设）→ 「从下标 0 开始」的子数组全部漏掉
```

★ **一句话：`mp[0] = 1` 是给「空区间」登记—— 前缀和 0 出现过 1 次。**

★ **记忆锚点：前缀和 + 哈希的题，见到 `mp` 就先写 `mp[0] = 1;`**（像 `i = 0` 一样的固定动作，不靠推理）。

★ **坑 2 很隐蔽**：代码看起来对、`mp[0]=1` 也写了，但 `pre[0]` 被「初始化」和「循环遍历 pre」各记一次 → 多算。

★ **结论：560 用 `cur` 增量版，不要预存 `pre` 数组**（哈希表本身就充当「历史前缀和的集合」）。

## 四·补、二维前缀和（304 区域和检索 2D）

题目：给二维矩阵，多次查询子矩形 `(r1,c1)~(r2,c2)` 的和。

### 4.5 ★ 定义与公式

```cpp
pre[i][j] = 从 (0,0) 到 (i-1, j-1) 的矩形和      // 半开，尺寸 (m+1) x (n+1)
```

**构造（容斥）**：
```cpp
pre[i][j] = pre[i-1][j] + pre[i][j-1] - pre[i-1][j-1] + matrix[i-1][j-1];
//           上面那块      左边那块      重叠减一次        当前格子
```

**查询（容斥）**：
```cpp
pre[r2+1][c2+1] - pre[r1][c2+1] - pre[r2+1][c1] + pre[r1][c1];
//  大矩形         减上面        减左边         加回左上角（被减两次）
```

★ **容斥口诀：构造「加两块、减重叠、加自己」；查询「减两条、加回左上角」。**

★ **本人独立推出上式**（画图推的，没背）—— 写好公式后可用边界自检：`r1=c1=0` 时后两项为 0，退化成 `pre[r2+1][c2+1]` ✓。

### 4.5b ★ 容斥的几何本质（构造 vs 查询）

★ **构造（两个大块求和 → 重叠部分被多算 → 减）**：

```
pre[i-1][j]  含：行 0..i-2，列 0..j-1     （上块）
pre[i][j-1]  含：行 0..i-1，列 0..j-2     （左块）
交集 = 行 0..i-2，列 0..j-2 = pre[i-1][j-1]   → 被算了两次 → 减一次
```

★ **查询（大块减两块 → 重叠部分被多减 → 加回）**：

```
        列 0..c1-1    列 c1..c2
行0..r1-1  ┌─────────┬───────────┐
           │ 左上角  │  上面条   │
           │(被减2次)│           │
           ├─────────┼───────────┤
行 r1..r2   │ 左边条  │  答案区域 │
           └─────────┴───────────┘
```

★ **「左上角」同时属于「上面条」和「左边条」→ 被减两次 → 加回一次（`pre[r1][c1]`）。**

### 4.5c ★ 构造 vs 查询：同一容斥，方向相反

| | 构造 | 查询 |
|---|---|---|
| 对象 | 两个大块**求和** | 大块**减**两块 |
| 重叠后果 | 被**多算** | 被**多减** |
| 操作 | **减**重叠 | **加**回重叠 |
| 重叠区 | `pre[i-1][j-1]` | `pre[r1][c1]` |

★ **符号相反**：构造是「加法里重叠 → 减」；查询是「减法里重叠 → 加」。⚠️ **别当“同理”混着用。**

★ **容斥出现在「两个不互相包含的块」时**：
- **一维**：`pre[r+1]` 与 `pre[l]` 是**前缀包含**关系 → 不相交 → 只减一项
- **二维**：两个块**相交** → 要补回交集

### 4.5d ★ 前缀和 = DP

★ **一维 / 二维前缀和的构造都是递推**：

| DP 要素 | 一维 | 二维 |
|---|---|---|
| 状态 | `pre[i]` | `pre[i][j]` |
| 转移 | `pre[i+1] = pre[i] + nums[i]` | `pre[i][j] = pre[i-1][j] + pre[i][j-1] - pre[i-1][j-1] + matrix[i-1][j-1]` |
| 边界 | `pre[0]=0` | 第 0 行 / 第 0 列 = 0 |
| 顺序 | `i` 递增 | `i`、`j` 都递增 |

★ **所以前缀和 ⊂ DP**（本人已在不知不觉中用了 DP 思想）。

★ **`pre` 第 0 行/列恒为 0 的作用**：让查询公式在「贴左/贴上边界」（`r1=0` 或 `c1=0`）时自动退化，**不用特判**。

### 4.6 ★ 「拍平」vs「二维前缀和」是两件事

⚠️ **本人两种都写过**，一度搞混它们各自的作用：

| | 拍平（连续内存）| 二维容斥 |
|---|---|---|
| 影响 | **常数**（cache）| **复杂度**（查询 O(m) → O(1)）|
| 不做的后果 | 慢一点点 | **慢很多（O(m)）**|

★ **决定复杂度的是「二维容斥」，不是「拍平」。**
★ **最优 = 二维容斥 + 拍平**，但只需前者就能 AC。

### 4.7 ★ 底层视角：内存连续性什么时候重要

⚠️ **本人问：`vector<vector>` 不连续会影响读取速率吗？**

★ **会，但取决于访问模式：**

| 访问模式 | 影响 |
|---|---|
| **顺序扫描大范围** | ⚠️ 有（跨行/跨节点每步 miss）|
| **少量随机访问** | 可忽略（本来就跳，跳几下无感）|

**`vector<vector<T>>` 哪里不连续：**
```
pre      [行0指针][行1指针][行2指针]   ← 顶层连续
            ↓         ↓        ↓
  行数据 [.. .. ..]  [.. .. ..]        ← 每行单独 malloc，行间不连续
```
- `pre[i]`（拿行）：✅ 连续；行内 `pre[i][j]`：✅ 连续
- **跨行** `pre[i][n-1] → pre[i+1][0]`：❌ 不连续（跳一块）

★ **所以 `vector<vector>` 只在「逐行遍历」时受影响；304 的查询一次只碰 4 个格子 → 无关。**
★ **304 的 75ms / beat 5% 是 LeetCode 测量抖动，不是内存问题**（查询已是 O(1) 最优）。
★ **同一原理**：本人 `matmul-opt` lab 的 L0 按列访问（大 stride）慢 —— 都是「cache line 只用 1/8」。详见 `速查手册/C++-内存与调度-速查.md` 第一节。

### 4.8 ⚠️ 本人踩坑

| # | 坑 | 正确做法 |
|---|---|---|
| 1 | **拍平公式乘了行数** | `row * 【列数】 + col`（乘的是列数！）|
| 2 | **内层循环用了 `m`（行数）** | 二维遍历：外层 `i<=m`、内层 `j<=n` |
| 3 | 先写「逐行一维前缀和」| 能 AC 但查询 O(m) → 应上二维容斥 |

★ **本人多次在「行/列（m/n）、±1」上出错** —— 建议**开头明写 `rows`/`cols`**，别用 `m`/`n`。

## 五、⚠️ 避坑清单

| # | 坑 | 正确做法 |
|---|---|---|
| 1 | 前缀和 `pre` 开 `n` 个 | 开 **`n+1`**（`pre[0]=0`）|
| 2 | 区间公式写成 `pre[r] - pre[l]` | 闭区间 `[l,r]` 用 **`pre[r+1] - pre[l]`** |
| 3 | 前缀和 / 差分用 `int` | 用 **`long long`**（防溢出）|
| 4 | 差分 `d` 开 `n` 个 | 开 **`n+1`**（防 `d[r+1]` 越界）|
| 5 | 差分还原循环写到 `i <= n` | 只到 **`i < n`**（`d[n]` 不参与）|
| 6 | **1-based 编号漏转**（1109）| 差分是 **`d[first-1]` / `d[last]`**（起点减 1，终点不减）|
| 7 | 560 忘记 `mp[0] = 1` | 必须先记「空区间」前缀和 0 |
| 8 | 560 预存 `pre` 数组 + 哈希 | 用 `cur` 增量版，避免 `pre[0]` 重复计数 |
| 9 | `nums` 用 `new` 后未初始化 | `new int[n]()` 或显式赋值（练习时的坑）|
| 10 | 空数组访问 `nums[0]` | UB！先判空 / 用范围 for |
| 11 | 二维拍平乘了行数 | `row * 【列数】 + col`（乘的是列数）|
| 12 | 二维遍历内层用 `m` | 内层上界是列数 `n` |

★ 容器的**内存布局 / 选型**见 `速查手册/C++-内存与调度-速查.md`。

---

## 七、一句话总结

> ★ **前缀和：`pre[i]` = 前 i 个之和 → 区间和 `pre[r+1] - pre[l]`（O(1)）。**
> ★ **差分：`d[i] = nums[i]-nums[i-1]` → 区间 `[l,r]` +v 只改 `d[l]+=v, d[r+1]-=v`（O(1)）；最后前缀和还原。**
>
> **两者互为逆运算**（一个累加得原数组，一个相减得差分）。
>
> **三个铁律：**
> 1. **数组开 `n+1`**（前缀和留 `pre[0]=0`；差分防 `d[r+1]` 越界）
> 2. **一律 `long long`**
> 3. **1-based 转 0-based：起点 `-1`，终点不减**
>
> **组合拳：前缀和 + 哈希 = 「多少个前缀和满足某关系」**（560，与 Two Sum 同源）。
>
> **思想：把「重复计算」预先合并（前缀和）或推迟结算（差分）。**

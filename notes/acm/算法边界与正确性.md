★ **「会用」和「知道什么时候不能用」是两种能力。**

```

```

★ **边界 = 正确性前提破裂的地方。**

```
若正确性依赖前提 P：
  P 成立 → 算法对
  P 不成立 → 证明失效   ← 但这不等于「算法一定错」！
```

## 〇·补、★ 关键区分：前提破坏 vs 算法失效

★★ **这是本笔记最重要的方法论：两件事必须分开写。**

| | **前提破坏** | **算法失效** |
|---|---|---|
| **是什么** | 证明所依赖的**依据**不成立 | 存在**具体输入**，让某种实现输出错误 |
| **性质** | 逻辑命题（推不出来）| 实证命题（能跑出反例）|
| **强度** | 弱 —— 算法**可能碰巧还对** | 强 —— **确定错** |
| **怎么得到** | 检查前提是否成立 | **构造输入 + 实际推演** |

### ★ 三档判断（比二分更实用）

| 档 | 含义 | 决策 |
|---|---|---|
| **① 前提成立** | 证明有效 | ✅ 放心用 |
| **② 前提破坏，但无具体反例** | 证明失效，但算法**可能仍对** | ⚠️ **不确定 → 要么补证，要么造反例** |
| **③ 有具体反例** | 确定错 | ❌ **不能用** |

★ **② 是最危险的地带**：你以为它错，其实可能对；你以为它对，可能只是没想到反例。

★ **诚实原则：没有具体反例时，标注「未验证」，不要写成「失效」。**

### ★ 反例的严谨格式

```
输入：具体数据
实现：哪种变体（同一题可能有多变体！）
输出：实际得到什么
期望：应该是什么
机制：为什么这个实现会错
```

★ **「滑窗不能解和为 K」的反例必须说明「哪种滑窗、怎么收缩」** —— 否则不算严谨。

## 二、第 0 层板块逐个过

### 2.1 滑动窗口

**核心前提**：窗口扩张/收缩时，状态**单调变化**（通常要求元素全正，使「和」单调不减）。

**一句话证明**：状态随窗口变大单调不减 → 一旦满足条件，再扩张只会更满足 → 所以收缩到「刚好满足」就是**以该 `right` 结尾的最优解**；不满足时必靠 `left` 右移才能满足（否则死循环）。

**前提破坏**：元素含负数 → 「窗口扩张则和增大」不再成立。

**具体反例**：
```
输入：nums = [1, -1, 1], k = 1（和为 K 的子数组）
实现：「和太大就缩、和太小就扩」的标准滑窗
失效机制：
  扩张可能让和【减小】（-1 进来），收缩可能让和【增大】（丢掉 -1）
  → 「和太小 → 扩张」这条决策规则失去意义
  → 会把「扩张后和变小」误判成「该继续缩」
结果：漏解
```
★ **结论：确定失效 → 必须换「前缀和 + 哈希」。**

**判定问句**：元素会不会是负数？（会 → 不能滑窗）

---

### 2.2 哈希表

**核心前提**：键可比较相等（可哈希）；且查询的语义是「之前遍历过的部分」。

**一句话证明**：「先查后记」保证表里只有 `[0, i-1]`，所以查到的配对一定不是自己；`mp[0]=1` 表示「空区间」，让「从下标 0 开始」的情况也被计入。

**前提破坏**：
1. 「先查后记」的顺序被破坏
2. `mp[0]=1` 缺失（空区间未登记）
3. 键类型不可哈希（数组、不可比较的结构）

**具体反例**：
```
① 输入：nums = [3,2,4], k = 6（两数之和）
   实现：先 mp[x]=i 再查 mp[k-x]
   实际：返回 {0,0}（自己配自己）
   期望：{1,2}
   机制：先记后查 → 读到刚插入的自己

② 输入：nums = [3], k = 3（和为 K 的子数组）
   实现：mp 初始为空（漏 mp[0]=1）
   实际：0
   期望：1
   机制：「从下标 0 开始」的子数组靠 mp[0] 才能被数到
```

**判定问句**：我要查的键，和我要插入的键，是同一个吗？

---

### 2.3 前缀和 / 差分

**核心前提**：运算**可逆**（加法、异或）；且元素**顺序固定**（不可重排）。

**一句话证明**：
- 前缀和：`pre[k]` = 前 k 个之和 → `pre[r+1] - pre[l]` 恰好覆盖 `nums[l..r]`，不多不少
- 差分：区间 `[l,r]` 全体 +v 后，区间内部相邻差不变，只有 `d[l]` 和 `d[r+1]` 变了；前缀和还原时 `+v` 从 `l` 传到 `r`，`r+1` 处被 `-v` 抵消

**前提破坏**：
1. 运算不可逆（乘法遇 0、取模、max/min）
2. 数组顺序可变（如允许重排）

**具体反例（③ 确定失效）**：
```
输入：nums = [2, 4, 0, 3], k = 0（求乘积为 k 的子数组个数）
实现：前缀积 + 哈希（pre[i] = nums[0]*...*nums[i-1]，查 pre[r+1] / pre[l] == k）
实际：在 i=1 处直接崩溃（cur / k = cur / 0 除零）
期望：正常计数
机制：k = 0 时除法本身就是非法运算
→ ③ 确定失效
```

**判定问句**：运算可逆吗？（加法/异或可以；乘法遇 0 不行）

#### ★ 2.3.1 「前提破坏」与「确定失效」的分界示范（本人实战辨析）

★ **这是一道很好的教材题：同一个失效机制，两种输入落在不同档位。**

**题目**：用「前缀积 + 哈希」求「乘积为 k 的连续子数组个数」（元素全正）。

**主张**：`pre[i] = nums[0]*…*nums[i-1]`，区间积 = `pre[r+1] / pre[l]`，再配哈希计数。

##### 前提

★ **运算可逆（除法），即前缀积非 0。**

##### 前提破坏

★ **数组含 0 → 从那个 0 开始，后续所有前缀积恒为 0，除法无法还原。**

##### ⚠️ 但「前提破了」≠「一定错」—— 看两个具体输入

**输入 A（② 地带：前提破了，但结果居然对）**
```
nums = [1, 1, 0], k = 1
前缀积 pre = [1, 1, 1, 0]
  i=1: cur=1, 查 mp[1/1]=mp[1] → 命中空积 1 → count=1
  i=2: cur=1, 查 mp[1] → 命中 → count=3
  i=3: cur=0, 查 mp[0/1]=mp[0] → 未命中 → count 不变

实际：3
期望：3（子数组 [1](0)、[1](1)、[1,1]）
→ ★ 结果对！虽然 0 破坏了前提，但这个具体输入没出错
→ 属于 ②（不能凭这一例就说「算法失效」）
```

**输入 B（③ 确定失效）**
```
nums = [2, 4, 0, 3], k = 0
实际：在第一步就 cur / k = cur / 0 → 除零（UB / 崩溃）
期望：正常输出
→ ★ 必错（不是「碰巧错」，是「一定会错」）
→ 属于 ③
```

##### ★ 结论（这个例子教什么）

| 现象 | 档位 |
|---|---|
| 「含 0 → 前缀积为 0」 | **②（仅现象）** |
| 「加入某个含 0 的输入，实际输出 = 期望」 | **仍是 ②** |
| 「k = 0 → 除法崩溃，必错」 | **③** |

★★ **教训：能说出「哪里破了」只是 ②；能说出「哪个输入下实际 ≠ 期望」才是 ③。**

★ **而且「前提破了」不等于「所有输入都错」—— 可能部分输入碰巧对。** 这就是 ② 这个地带存在的真正原因。

### 2.4 二分查找

**核心前提**：**存在单调性**（不是「有序」—— 有序只是单调性的特例）。

**一句话证明**：每次迭代区间**严格缩小**：
- `mid = left + (right-left)/2`（向下取整）保证 `mid < right` → `right = mid` 让右界严格减小
- `mid >= left` → `left = mid+1` 让左界严格增大

→ 区间必然收敛到 `left == right`，即「第一个满足条件的位置」。

**前提破坏**：
1. 无单调性（数组无序且无特殊结构）
2. `mid` 取整方向与赋值方向不匹配（`left = mid` 配向下取整 → 区间不缩小）

**具体反例**：
```
① 输入：nums = [3,1,4,1,5,9]（无序），找 4
   实现：标准二分
   实际：可能返回 -1
   期望：下标 2
   机制：无单调性 → 「mid 小于 target 就向右」不成立

② 输入：任意（寻找「最后一个 <= target」）
   实现：mid 向下取整 + left = mid
   实际：死循环（如 left=0, right=1, mid=0，nums[0] <= target → left 仍为 0）
   机制：区间不缩小
```

**判定问句**：能不能找到一个「分界点」，左边全假、右边全真？

---

### 2.5 二分答案

**核心前提**：`can(答案)` 关于答案**单调**（通常「答案越大越容易满足」）。

**一句话证明**：`can` 单调 → 存在唯一的翻转点 → 二分找「第一个 `can == true`」即最优；`right = mid`（不是 `mid-1`）是因为 mid 本身可能就是答案。

**前提破坏**：
1. `can` 不单调（存在「可行-不可行-可行」的震荡）
2. `lo` 取值非法（如小于「单个元素的最小可能」）

**具体反例**：
```
输入：（假设）某题 can(x) = 「x 是偶数」 → 真假交替
实现：二分答案
实际：找不到「第一个 true」
机制：不单调 → 翻转点不唯一 / 不存在
⚠️ 这是理论反例；LeetCode 上二分答案题的 can 都是单调的（题目保证）
```

**判定问句**：候选答案变大时，满足条件会不会「只从假变真、不会变回去」？

### 2.6 排序

**核心前提**：比较器满足**严格弱序**（`comp(a,a) == false`，且传递）。

**一句话证明**：`sort` 内部依赖全序关系做分区与合并；若 `comp(a,a)` 为真，分区会自比较 → 违反算法前提 → UB。

**前提破坏**：比较器写 `<=` / `>=`；多关键字逻辑写错。

**具体反例**：
```
输入：v = {2, 2, 1}
实现：sort(v, [](a,b){ return a <= b; })
结果：可能崩溃 / 死循环 / 结果乱序（UB，行为不确定）
机制：comp(2,2) == true → 违反严格弱序
```

**判定问句**：这个比较器，对「相等的两个元素」返回 false 吗？

---

### 2.7 贪心

**核心前提**：**局部最优能推出全局最优**（无后效性 / 交换论证成立）。

**一句话证明**：交换论证 —— 若存在最优解不含贪心选择，则可通过交换把它变成含贪心选择的最优解 → 贪心选择不劣。

**前提破坏**：当前选择会「害了后面」（后效性）。

**具体反例**：
```
输入：面额 [1, 3, 4]，凑 6
实现：每次取不超过余额的最大面额
实际：4 + 1 + 1 = 3 枚
期望：3 + 3 = 2 枚
机制：取 4 之后剩下的 2 只能用两个 1 → 局部最优害了后面
```

**区间贪心的两个不同判据**：
| 目标 | 排序键 | 为什么 |
|---|---|---|
| 选最多（腾空间）| 右端点 | 结束早 → 后面可选多 |
| 合并（连成链）| 左端点 | 按起点才能顺序判断能否接上 |

**判定问句**：这一步的选择，会不会「害了后面」？

---

### 2.8 对撞双指针

**核心前提**：每步能**确定性地排除一端**（依赖有序性 / 单调关系）。

**一句话证明**：
- 两数之和：`sum` 太小 → `nums[left]` 与任何右侧元素配对都太小 → **整行废**（同理 `sum` 太大整列废）→ 每步排除 n 个可能 → 总 O(n)
- 盛水容器：宽度只会减小 → 移高的 `min` 不变或更小、宽度还减 → 面积只会变小 → **移高的无意义**

**前提破坏**：数组无序且无单调关系 → 不知道动哪端。

**具体反例**：
```
输入：nums = [4, 7, 1, 9], target = 8（无序）
实现：标准对撞（sum 小 → left++）
推演：left=0(4), right=3(9) → sum=13 > 8 → right-- → 1+4=5 < 8 → left++ → 7+1=8 ✓
      此题碰巧对！但：
输入：nums = [9, 1, 4, 7], target = 8
      left=0(9), right=3(7) → sum=16 > 8 → right-- → 9+4=13 → right-- → 9+1=10 → right--，擦肩而过 → 返回未找到
期望：{1,3}（1+7）
→ 确定失效
```

**判定问句**：动这一端，能不能「安全排除」它与其他所有元素的所有组合？

### 2.9 快慢指针（数组版）

**核心前提**：只需**原地修改**，且需**保留元素的相对顺序**。

**一句话证明**：`slow` 之前是「已处理好的结果」，`fast` 负责读；`fast` 扫完时 `slow` 恰好等于结果长度 —— 每个元素被读一次、被写至多一次 → O(n) 且保序。

**前提破坏**：
1. 需要乱序（如「把所有 0 换到前面」）→ swap 版仍可用，但「保序」不成立
2. 需要在 `slow` 之前区域做「非前缀」访问

**具体反例**：
```
⚠️ 未构造出「确定失效」的具体反例 —— 快慢指针（数组版）在「原地 + 保序」场景下基本总是对的。
（仅当题目要求「非保序」时才需换成 swap 版本，这不是「失效」，而是「换变体」）
```

**判定问句**：题目允许用额外空间吗？（不允许 + 要保序 → 快慢指针）

### 2.10 单调队列 / 单调栈

**核心前提**：元素的**支配关系**成立 —— 被淘汰的元素**既不如新元素优，又比新元素更早失效**。

**一句话证明**：
- 单调队列（踢尾）：被踢的元素值 ≤ 新元素（新元素在时它当不了最值），且下标更小（更早过期）→ **它在新元素的整个有效期内都不可能是答案** → 踢掉无损失
- 单调栈：栈内递减 → 新元素来时弹出所有比它小的，这些元素的「下一个更大」就是新元素（第一个满足的）→ 每个元素进出栈各一次 → O(n)

**前提破坏**：
1. 被淘汰元素「可能后来居上」（如需要「历史最大值」而不仅是「当前窗口最大值」）
2. 要求「任意方向/任意距离」的查找（单调栈只能给「下一个」）

**具体反例**：
```
输入：nums = [5, 3, 4], 求「每个元素的【后面所有】更大元素之和」
实现：单调栈（只弹一次）
失效机制：3 的后面有 4 和 5（但 5 在 3 之前，不算「后面」）—— 
          若需求改成「整个数组中的更大元素」，单调栈就失效（它只保证「下一个」）
⚠️ 具体输入需按题目定制；核心是：单调栈的答案「一旦弹出就定了」，若需求是「多次查找」则不适用
```

**判定问句**：有没有「窗口滑动」？（有 → 队列；无，只是方向性查找 → 栈）

## 三、★ 跨板块辨析表（三行格式）

★ **每组都按「分界线 / 前提破坏 / 具体反例」写。**

### 3.1 滑窗 vs 前缀和 + 哈希

- **分界线**：元素是否**全正**（状态是否单调）
- **前提破坏**：有负数 → 滑窗的单调性前提失效
- **具体反例**：`nums = [1,-1,1], k=1` → 标准滑窗漏解（详见 2.1）

### 3.2 对撞 vs 滑窗 vs 快慢

- **分界线**：**方向**（相向 / 同向等距 / 同向不同职责）
- **前提破坏**：对撞在无序数组上失效
- **具体反例**：`nums=[9,1,4,7], target=8` → 对撞擦肩而过（详见 2.8）

### 3.3 贪心 vs DP

- **分界线**：**局部最优能否推全局**（有无后效性）
- **前提破坏**：选择会害后面
- **具体反例**：凑零钱 `[1,3,4]` 凑 6 → 贪心 3 枚、最优 2 枚

### 3.4 二分查找 vs 二分答案

- **分界线**：二分的是**数组下标**还是**答案的取值**
- **前提破坏**：二分答案要求 `can` 单调；二分查找要求数组单调
- **具体反例**：无序数组 `[3,1,4,1,5,9]` 找 4 → 二分失败

### 3.5 DFS vs BFS

- **分界线**：要**「最短步数」**还是**「所有方案 / 能否到达」**
- **前提破坏**：DFS 求最短 → 第一次到达不是最短
- **具体反例**：网格 `A→B→D`（3 步）而实际 `A→C→D`（2 步），DFS 先到 D 时无法判断最短
- **★ 底层统一视角**：同一个遍历框架，换容器 = 换算法（队列→BFS、栈→DFS、deque→0-1 BFS、堆→Dijkstra、堆+估价→A*）

### 3.6 单调栈 vs 单调队列

- **分界线**：**有没有「窗口滑动」**
- **前提破坏**：需要「多次/任意方向查找」时单调栈不适用
- **具体反例**：求「每个元素后面所有更大元素之和」→ 单调栈只给「下一个」，失效

### 3.7 前缀和 vs 差分

- **分界线**：求「区间和」还是「区间加值」（互为逆运算）
- **前提破坏**：运算不可逆
- **具体反例**：前缀积遇 0（详见 2.3）

### 3.8 哈希集合 vs 哈希映射 vs 有序 map

- **分界线**：只需「存在」/ 需要「值→信息」/ 需要「有序或前驱后继」
- **前提破坏**：用 `unordered_map` 却需要有序遍历
- **具体反例**：需要「找比 x 大的最小键」→ `unordered_map` 无法做（O(n) 扫描），必须 `map`/`set`

## 六、★ 平时的三个训练动作

### 训练 1：一句话证明（每做完一题）

```
问自己：为什么这样不会漏？为什么这样对？
写一句。写不出来 → 这题只是背会了。
```

### 训练 2：改条件测试（每做完一题）

```
问自己：改掉哪个前提，这算法就不成立了？
→ 再问：是「前提破坏」还是「真的能构造出反例」？
```

★ **第二步是关键 —— 逼你区分 ② 和 ③。**

★ **判据（背这一句）：**
```
能写出「实际输出 = X，期望输出 = Y，X ≠ Y」吗？
  能   → ③ 确定失效
  不能 → ② 前提破坏（诚实标注，别偷懒升格）
```

★ **注意反向陷阱：前提破了，部分输入可能碰巧还是对的**（见 §2.3.1 的 `[1,1,0], k=1`）—— 这就是 ② 地带存在的真正原因。

### 训练 3：三题互相比（每学完一个板块）

```
找一道相邻板块的题，写一张分界表：分界线 / 前提破坏 / 具体反例
```

## 八、一句话总结

> ★ **边界 = 正确性前提破裂的地方。**
> ★ **但「前提破坏」≠「算法一定错」—— 要区分：**
> - **前提破坏**：证明失效（逻辑）
> - **具体反例**：有输入跑出错误（实证）
> - **② 地带**：前提破了但没反例 → 诚实地标「未验证」
> ★ **严谨的反例 = 输入 + 具体实现 + 实际 vs 期望 + 失效机制。**
> ★ **「前提破了」只是 ②；「实际 ≠ 期望」才是 ③。** 而且前提破了不代表所有输入都错（可能部分碰巧对）。
> ★ **最有效的训练：做完每题，问「改哪个条件它就不成立了」，然后追问「是前提破坏还是真反例」。**
